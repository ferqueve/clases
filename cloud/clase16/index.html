Concepto · instancia

Una instancia es una máquina virtual alquilada

i-0a1cliente A · t3.small
i-7f2cliente B · t3.micro
i-0a2cliente A · t3.small
i-7f3cliente B · c7i.large
hipervisor del proveedoraísla a cada cliente
servidor físico · CPU · RAM · redcentro de datos

Es lo mismo que hicimos en el laboratorio de VirtualBox, con tres diferencias: el hardware no es tuyo, se pide por API y se paga mientras corre.

multi-inquilino

En el mismo servidor físico conviven instancias de clientes distintos. El hipervisor impide que una vea la memoria o los discos de otra.

Concepto · tamaño

vCPU y memoria: de qué está hecho un tipo

Un tipo de instancia fija cuántas vCPU y cuánta memoria recibe la máquina. No se elige “4 GB y 3 CPU”: se elige un tipo del catálogo.

vCPU

En procesadores Intel y AMD, una vCPU es un hilo de un núcleo físico, así que 2 vCPU equivalen a un núcleo con sus dos hilos. En procesadores ARM, como Graviton, una vCPU es un núcleo completo.

TipovCPUMemoria
t2.micro11 GiB
t3.micro21 GiB
t3.small22 GiB
t3.medium24 GiB
m7i.large28 GiB
c7i.large24 GiB

Mismo número de vCPU, distinta memoria: eso es lo que separa a las familias. En la práctica vamos a medir estos límites.

Concepto · familia t

Instancias con ráfagas: créditos de CPU

Las instancias de la familia t son baratas porque no garantizan el 100 % de la CPU todo el tiempo. Tienen una línea base: por ejemplo, una t3.micro tiene garantizado el 10 % de cada vCPU.

noche · 4 %
mañana · 8 %
pico · 85 %

La raya blanca marca la línea base del 10 %.

debajo de la línea base

La instancia acumula créditos. Es lo normal en un servidor web con poco tráfico.

por encima

Gasta créditos para correr a más velocidad. Si se le terminan, en modo standard vuelve a la línea base; en modo unlimited sigue rápida y se cobra el excedente.

Concepto · imagen

La imagen: con qué arranca la instancia

Una imagen (en AWS, AMI) es una plantilla de disco. Cada instancia nace como una copia de ella.

contiene
  • El disco raíz: sistema operativo y software instalado
  • Quién puede usarla: pública, privada o compartida con otras cuentas
  • Qué discos se conectan al arrancar y en qué dispositivo
de dónde salen

Del proveedor, como Amazon Linux o Ubuntu oficial. De terceros, en el marketplace, a veces con costo de licencia. Propias, capturadas de una instancia ya configurada.

son regionales

Una AMI existe en una sola región. La misma Ubuntu tiene un ID distinto en us-east-1 y en sa-east-1. Para usarla en otra región, hay que copiarla.

Concepto · ciclo de vida

Estados de una instancia y qué se cobra

pendingse asigna un servidor físico y se copia la imagen
runningarranca el sistema operativo
stoppedapagada; el disco se conserva
terminatedborrada para siempre
Estado¿Cobra cómputo?¿Cobra disco?¿Se puede volver atrás?
runningSí, por segundoSí—
stoppedNoSíSí: start
terminatedNoNo, salvo volúmenes que se conservanNo

Reiniciar no es apagar. Un reboot mantiene la instancia en el mismo servidor físico. Un stop y start puede moverla a otro, y cambia la IP pública.

Concepto · configuración

User data: el script del primer arranque

ejemplo de user data
#!/bin/bash
dnf update -y
dnf install -y nginx
systemctl enable --now nginx
cuándo corre

Una sola vez, en el primer arranque, como usuario root. Un reinicio no lo vuelve a ejecutar.

quién lo corre

cloud-init, un programa preinstalado en casi todas las imágenes de nube. Lee el script desde el servicio de metadatos y lo ejecuta.

límite

Viaja codificado en base64 y tiene un tamaño máximo de 16 KB. Para algo más grande, el script descarga el resto.

Concepto · estrategia

¿Hornear la imagen o configurar al arrancar?

imagen horneada (golden image)

Todo instalado de antemano

  • La instancia arranca lista en segundos
  • Todas las copias son idénticas
  • No depende de internet ni de repositorios al arrancar
  • Cada cambio exige crear una imagen nueva
configuración en el arranque

Imagen genérica + user data

  • Un solo script, fácil de cambiar
  • Siempre instala las versiones más nuevas
  • Arrancar tarda más, a veces minutos
  • Si un repositorio falla, la instancia nace rota

En la práctica se combinan: una imagen con lo pesado ya instalado y un user data corto que aplica la configuración final.

Concepto · metadatos

IMDS: la instancia pregunta quién es

Desde adentro de cualquier instancia hay una dirección especial, 169.254.169.254, que responde datos sobre esa misma instancia: su ID, su tipo, su IP, su zona, su user data y credenciales temporales.

VersiónCómo se pide
IMDSv1Un GET directo, sin más
IMDSv2Primero un PUT que entrega un token; después cada GET lleva ese token
por qué existe IMDSv2

Protección contra SSRF

Si una aplicación web tiene un fallo que permite que un atacante le haga pedir cualquier URL, con IMDSv1 podría leer las credenciales de la instancia con un simple GET. El PUT previo y el encabezado del token bloquean ese ataque.

Hoy se recomienda exigir IMDSv2 en todas las instancias.

Concepto · plantillas

Plantillas de lanzamiento

Una launch template guarda todos los parámetros de una instancia: imagen, tipo, claves, red, etiquetas y user data. Después se lanza con un solo parámetro.

versionadas

Cada cambio crea una versión nueva: v1 con t3.micro, v2 con t3.small. Una de ellas se marca como versión por defecto.

por qué importan

Evitan errores de tipeo y hacen que todas las instancias de un mismo rol sean iguales.

próximamente

El escalado automático (módulo 7) usa una plantilla para saber qué instancias crear cuando sube la demanda.

Una diferencia que vamos a ver: un contenedor comparte el kernel con tu PC. Por eso, adentro, /proc/meminfo muestra la memoria total de tu máquina, aunque el contenedor tenga un límite de 1 GiB. En una máquina virtual real mostraría 1 GiB.

Práctica 2 · Lanzar la primera instancia

PowerShell
$WEBA = aws ec2 run-instances `
  --image-id ami-amazonlinux2023 `
  --instance-type t2.micro `
  --tag-specifications "ResourceType=instance,Tags=[{Key=Name,Value=web-a},{Key=Proyecto,Value=modulo-computo}]" `
  --query "Instances[0].InstanceId" --output text

# Estado de la instancia (repetir hasta ver running)
aws ec2 describe-instances --instance-ids $WEBA `
  --query "Reservations[0].Instances[0].State.Name"

# La misma instancia, vista desde Docker
docker ps --format "table {{.ID}}\t{{.Image}}\t{{.Names}}\t{{.Status}}"
sin red explícita

No indicamos subred ni security group, así que la instancia va a la VPC y al grupo por defecto. Las redes las vemos en el módulo 4.

etiqueta Proyecto

Todas las instancias del módulo llevan Proyecto=modulo-computo. Al final la usamos para borrarlas de una vez.

Práctica 3 · ¿El tipo cambia algo de verdad?

PowerShell
# Guardar el ID de app-1
$APP1 = aws ec2 describe-instances `
  --filters "Name=tag:Name,Values=app-1" `
  --query "Reservations[0].Instances[0].InstanceId" --output text

# Límite de memoria y CPU de cada contenedor
docker stats --no-stream `
  --format "table {{.Name}}\t{{.CPUPerc}}\t{{.MemUsage}}"

# Dentro de una instancia: el límite y lo que "ve"
docker exec <contenedor> cat /sys/fs/cgroup/memory.max
docker exec <contenedor> head -1 /proc/meminfo
qué esperar

En la columna de memoria, web-a muestra un límite de 1 GiB y app-1, de 2 GiB. Son los valores de la tabla del catálogo.

memory.max

Devuelve el límite en bytes: 1073741824 es 1 GiB.

/proc/meminfo

Muestra la memoria de tu PC, no el límite. Es la diferencia entre contenedor y máquina virtual de la diapositiva 12.

Práctica 4 · Preguntarle a la instancia quién es

PowerShell → dentro de web-a
docker exec -it <contenedor-de-web-a> bash

# IMDSv1: un GET directo
curl -s http://169.254.169.254/latest/meta-data/instance-id; echo

# IMDSv2: primero el token...
TOKEN=$(curl -s -X PUT http://169.254.169.254/latest/api/token \
  -H "x-aws-ec2-metadata-token-ttl-seconds: 300")

# ...y después cada pedido lo lleva
curl -s -H "x-aws-ec2-metadata-token: $TOKEN" \
  http://169.254.169.254/latest/meta-data/placement/availability-zone; echo

# Todo junto, en JSON
curl -s http://169.254.169.254/latest/dynamic/instance-identity/document
exit
ojo con la terminal

Después de docker exec -it estás en bash, dentro de Linux. Por eso la continuación de línea es \ y no el acento grave de PowerShell.

¿cuál es el contenedor?

Si hay dudas, entrá a cualquiera y pedí el instance-id: compará con $WEBA.

Práctica 5 · Configurar en el arranque

arranque.sh · guardar con fin de línea LF
#!/bin/bash
echo "rol=worker" > /etc/lab-rol
date > /etc/lab-configurado
PowerShell
$CFG = aws ec2 run-instances `
  --image-id ami-amazonlinux2023 --instance-type t3.micro `
  --user-data file://arranque.sh `
  --tag-specifications "ResourceType=instance,Tags=[{Key=Name,Value=cfg-1},{Key=Proyecto,Value=modulo-computo}]" `
  --query "Instances[0].InstanceId" --output text

# ¿Corrió el script?
docker exec <contenedor-de-cfg-1> cat /etc/lab-rol

# Así lo guarda AWS: en base64
$B64 = aws ec2 describe-instance-attribute --instance-id $CFG `
  --attribute userData --query UserData.Value --output text
[Text.Encoding]::UTF8.GetString([Convert]::FromBase64String($B64))
sin internet

El script solo escribe archivos, así que funciona aunque el aula no tenga buena conexión.

CRLF

Si /etc/lab-rol no existe, lo más probable es que el archivo se guardó con fin de línea de Windows. En VS Code, abajo a la derecha: CRLF → LF.

base64

La CLI codifica el script al enviarlo y la API lo devuelve codificado. La última línea lo decodifica.

Práctica 6 · Recorrer el ciclo de vida

PowerShell
# Apagar web-a y esperar
aws ec2 stop-instances --instance-ids $WEBA
aws ec2 wait instance-stopped --instance-ids $WEBA

# El contenedor sigue existiendo, detenido
docker ps -a --filter "status=exited"

# Encender y reiniciar
aws ec2 start-instances --instance-ids $WEBA
aws ec2 wait instance-running --instance-ids $WEBA
aws ec2 reboot-instances --instance-ids $WEBA

# Estado de cada instancia del módulo
aws ec2 describe-instances `
  --filters "Name=tag:Proyecto,Values=modulo-computo" `
  --query "Reservations[].Instances[].[Tags[?Key=='Name']|[0].Value,InstanceType,State.Name]" `
  --output table
stopped = docker stop

El contenedor se detiene pero conserva su disco. Lo que se escribió adentro sigue ahí al volver a encender.

wait

aws ec2 wait consulta el estado una y otra vez hasta que se cumple. Sirve en scripts para no avanzar antes de tiempo.

la consulta final

Tags[?Key=='Name'] busca, entre todas las etiquetas, la que se llama Name. Es lenguaje JMESPath.

Práctica 7 · Crear una plantilla con dos versiones

plantilla.json · crear en VS Code
{
  "ImageId": "ami-amazonlinux2023",
  "InstanceType": "t3.micro",
  "TagSpecifications": [{
    "ResourceType": "instance",
    "Tags": [
      { "Key": "Proyecto", "Value": "modulo-computo" },
      { "Key": "Origen", "Value": "plantilla" }
    ]
  }]
}
plantilla-v2.json
{ "InstanceType": "t3.small" }
PowerShell
# Versión 1
aws ec2 create-launch-template `
  --launch-template-name plantilla-web `
  --version-description "v1 t3.micro" `
  --launch-template-data file://plantilla.json

# Versión 2: hereda todo de la 1 y cambia el tipo
aws ec2 create-launch-template-version `
  --launch-template-name plantilla-web `
  --source-version 1 `
  --version-description "v2 t3.small" `
  --launch-template-data file://plantilla-v2.json

# Ver las versiones
aws ec2 describe-launch-template-versions `
  --launch-template-name plantilla-web `
  --query "LaunchTemplateVersions[].[VersionNumber,VersionDescription,LaunchTemplateData.InstanceType]" `
  --output table

# Lanzar desde la versión 1
aws ec2 run-instances `
  --launch-template LaunchTemplateName=plantilla-web,Version=1

--source-version 1 es clave: sin él, la versión 2 empezaría vacía y solo tendría el tipo de instancia.

Práctica 8 · Desafío: hornear una imagen propia

PowerShell
# Capturar cfg-1 como imagen nueva
$AMI = aws ec2 create-image --instance-id $CFG `
  --name imagen-worker-v1 --query ImageId --output text
aws ec2 describe-images --image-ids $AMI

# Lanzar desde esa imagen, SIN user data
aws ec2 run-instances --image-id $AMI --instance-type t3.micro `
  --tag-specifications "ResourceType=instance,Tags=[{Key=Name,Value=desde-imagen},{Key=Proyecto,Value=modulo-computo}]"

# ¿Trae el archivo que escribió el script original?
docker exec <contenedor-de-desde-imagen> cat /etc/lab-rol
qué demuestra

Si aparece rol=worker, la configuración viajó dentro de la imagen. Esta es la estrategia de la diapositiva 9.

reinicio

create-image reinicia la instancia de origen para capturar el disco en un estado consistente, salvo que se use --no-reboot.

DocenteEste paso depende de cómo Floci captura el disco del contenedor. Probalo antes de clase: si el archivo no aparece, presentalo como demostración conceptual.
Limpieza

Terminar todo lo del módulo

PowerShell
# Todas las instancias con la etiqueta del módulo, sin importar su estado
$TODAS = (aws ec2 describe-instances `
  --filters "Name=tag:Proyecto,Values=modulo-computo" "Name=instance-state-name,Values=pending,running,stopping,stopped" `
  --query "Reservations[].Instances[].InstanceId" --output text) -split "\s+"

aws ec2 terminate-instances --instance-ids $TODAS
aws ec2 wait instance-terminated --instance-ids $TODAS

# La plantilla y sus versiones
aws ec2 delete-launch-template --launch-template-name plantilla-web

# Comprobar que Docker quedó limpio
docker ps -a

Etiquetar todo desde el principio es lo que permite este borrado en un solo paso. En una cuenta real, también se borraría la imagen propia con deregister-image.
