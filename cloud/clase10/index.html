Módulo 10 · Tecnologías y modelos de servicios

El catálogo no termina en IaaS/PaaS/SaaS

Esos tres fueron el punto de partida. Hoy vemos el resto del alfabeto "XaaS" y las tecnologías que conectan todo entre sí — APIs, colas de mensajes, CDN — el plomería que rara vez se ve pero sostiene cualquier arquitectura cloud real.

CaaS / DBaaS APIs CDN
El mismo patrón, aplicado a todo

El alfabeto "XaaS"

La lógica de IaaS/PaaS/SaaS —convertir algo que antes administrabas vos en un servicio que consumís— se repite una y otra vez sobre distintas piezas de la infraestructura.

DBaaS

Base de datos como servicio: el proveedor administra backups, replicación y parches del motor.

CaaS

Contenedores como servicio: corrés contenedores sin administrar el cluster de orquestación por debajo.

STaaS

Storage como servicio: capacidad de almacenamiento elástica, facturada por uso — como el S3 de AWS.

La base de datos que no administrás

DBaaS en profundidad

Ejemplos

Amazon RDS, Azure SQL Database, Google Cloud SQL, MongoDB Atlas.

Ventaja

Backups automáticos, réplicas de alta disponibilidad y parches de seguridad sin que nadie del equipo tenga que ejecutarlos a mano.

Trade-off

Menos control sobre configuración fina del motor, y suele costar más que administrar la base uno mismo en una VM.

Contenedores sin administrar el cluster

CaaS en profundidad

Recordemos Docker Swarm y Kubernetes del laboratorio de Escalabilidad: alguien tiene que administrar esos nodos. CaaS le saca esa capa al usuario — se sube un contenedor y el proveedor decide dónde y cómo correrlo.

Ejemplos

AWS Fargate, Google Cloud Run, Azure Container Instances.

Dónde se ubica

Es un punto intermedio entre el Docker Swarm que armaron a mano y el serverless total — administrás la imagen, no el cluster.

Dos siglas más, para completar el mapa

MBaaS y DaaS

MBaaS (Mobile Backend as a Service)

Autenticación, base de datos en tiempo real y notificaciones push listas para usar desde una app móvil — Firebase es el ejemplo más conocido, y lo vamos a ver en la Clase de Cloud Móvil.

DaaS (Desktop as a Service)

Un escritorio completo de Windows/Linux corriendo en la nube, accedido remotamente — útil para call centers o personal temporal sin entregar hardware físico.

El idioma común entre servicios

APIs y REST

Ningún servicio cloud vive aislado — todos se comunican entre sí a través de APIs. REST es el estilo más común: cada recurso tiene una URL, y se opera sobre él con verbos HTTP estándar.

GET

Leer un recurso sin modificarlo.

POST

Crear un recurso nuevo.

PUT / DELETE

Actualizar o eliminar un recurso existente.

Cuando creamos una instancia con la consola web de un proveedor, por detrás la consola está llamando exactamente a esas mismas APIs.

Cuando el contenido viaja lejos

CDN (Content Delivery Network)

Una CDN distribuye copias de contenido estático (imágenes, video, JS/CSS) en servidores repartidos geográficamente, para que cada usuario lo reciba desde el punto más cercano.

Por qué importa

Reduce latencia drásticamente y descarga tráfico del servidor de origen.

Ejemplos

Cloudflare, Amazon CloudFront, Akamai — las mismas que probablemente sirvieron esta página.

Cuando dos servicios no necesitan hablar en el momento

Colas de mensajes

En vez de que un servicio llame directo a otro y espere respuesta, deja un mensaje en una cola — y el otro servicio lo procesa cuando puede. Desacopla los sistemas y absorbe picos de tráfico.

Ejemplos

Amazon SQS, RabbitMQ, Apache Kafka.

Por qué se usa

Si el servicio receptor está caído o saturado, el mensaje espera en la cola en vez de perderse — otra forma más de redundancia.

Comunicación asíncrona como otra herramienta más de resiliencia.
