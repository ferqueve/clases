Concepto

¿Qué es OpenStack?

OpenStack es una plataforma abierta para construir nubes privadas o públicas. Permite administrar recursos de cómputo, red y almacenamiento desde APIs y desde un panel web.

En lugar de crear una VM manualmente en VirtualBox o VMware, OpenStack permite pedir infraestructura como servicio: instancias, redes, volúmenes, imágenes y seguridad.

¿Para qué sirve?

Crear VMs

Instancias bajo demanda con imágenes base.

Redes virtuales

Routers, subredes, IP flotante y reglas de seguridad.

Almacenamiento

Volúmenes persistentes, objetos e imágenes.

Automatizar

APIs, CLI y plantillas para despliegues repetibles.

Antes de instalar: recordatorio de red NAT

La VM está en NAT: desde el host no entramos directo a la IP interna de Ubuntu.

Por eso configuramos reenvío de puertos en VirtualBox:

Host: 127.0.0.1 puerto 2222 VM Ubuntu: puerto 22

Si se olvidaron de esto, PuTTY no conecta.

PuTTY Host Name: 127.0.0.1 Port: 2222 Connection type: SSH Usuario: el usuario de Ubuntu Contraseña: la definida en la VM

Objetivo del laboratorio

Entre hoy y la próxima clase del viernes vamos a instalar OpenStack en una VM Ubuntu y validar que podemos operar una nube mínima.

  • Conectarse por SSH usando PuTTY.
  • Preparar Ubuntu y dependencias.
  • Instalar OpenStack con DevStack para entorno académico.
  • Entrar al dashboard Horizon.
  • Crear una instancia de prueba, red y reglas básicas.

Requisitos sugeridos de la VM

Recursos

  • Ubuntu Server 24.04 o 22.04.
  • 8 GB RAM mínimo; mejor 12 GB.
  • 4 vCPU si es posible.
  • 60 GB de disco o más.

Importante

DevStack es para laboratorio/desarrollo. No es una instalación de producción.

Para producción se usan distribuciones y herramientas más robustas: Canonical OpenStack, Kolla-Ansible, OpenStack-Ansible, TripleO, etc.

Paso 1: conectar por PuTTY

Host Name: 127.0.0.1 Port: 2222 Connection type: SSH

Primera comprobación dentro del servidor:

whoami ip a ping -c 3 8.8.8.8 ping -c 3 google.com

Si falla Internet, revisamos NAT, DNS o la configuración de red de la VM.

Paso 2: actualizar Ubuntu

sudo apt update sudo apt upgrade -y sudo apt install -y git curl vim net-tools python3-pip

Luego reiniciamos si el sistema lo pide:

sudo reboot

Después del reinicio, volvemos a entrar por PuTTY con 127.0.0.1:2222.

Paso 3: crear usuario stack

DevStack no debe ejecutarse como root. Creamos un usuario dedicado.

sudo useradd -s /bin/bash -d /opt/stack -m stack sudo chmod +x /opt/stack echo "stack ALL=(ALL) NOPASSWD: ALL" | sudo tee /etc/sudoers.d/stack sudo -u stack -i

Desde este punto, el prompt debería indicar que estamos como usuario stack.

Paso 4: descargar DevStack

git clone https://opendev.org/openstack/devstack cd devstack

Creamos un archivo de configuración simple para laboratorio:

nano local.conf

Paso 5: local.conf mínimo

[[local|localrc]] ADMIN_PASSWORD=Secret123 DATABASE_PASSWORD=$ADMIN_PASSWORD RABBIT_PASSWORD=$ADMIN_PASSWORD SERVICE_PASSWORD=$ADMIN_PASSWORD HOST_IP=127.0.0.1 # Laboratorio académico: servicios básicos ENABLED_SERVICES+=,horizon

Para clase usamos una contraseña simple. En un entorno real, jamás.

Paso 6: ejecutar instalación

./stack.sh

La instalación puede tardar bastante porque descarga dependencias, configura servicios y levanta OpenStack.

Al final debería mostrar URLs, usuario y contraseña para acceder a Horizon.

Acceso a Horizon con NAT

Como la VM está en NAT, para abrir el panel web desde el host conviene crear un túnel SSH en PuTTY.

En PuTTY

Connection → SSH → Tunnels

Source port: 8080 Destination: 127.0.0.1:80 Add

En el navegador del host

http://127.0.0.1:8080/dashboard

Usuario habitual: admin
Contraseña: Secret123

Validación por consola

Cargamos credenciales y consultamos el estado básico:

cd /opt/stack/devstack source openrc admin admin openstack service list openstack image list openstack network list openstack flavor list

Si estos comandos responden, ya tenemos una nube mínima funcionando.

Laboratorio práctico

  1. Entrar a Horizon.
  2. Revisar proyectos, usuarios y servicios.
  3. Crear o verificar una imagen CirrOS.
  4. Crear una red interna y un router si corresponde.
  5. Crear una instancia pequeña.
  6. Agregar reglas ICMP y SSH en el Security Group.
  7. Documentar capturas y problemas encontrados.
