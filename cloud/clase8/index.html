Desplegar es el principio, no el final

Hasta ahora vimos cómo crear infraestructura. Hoy vemos qué pasa el día después: monitorear, dar accesos, parchear, controlar el gasto y automatizar — el trabajo que realmente ocupa la mayoría del tiempo de un equipo de infraestructura.

Monitoreo Usuarios y accesos Infrastructure as Code
El cambio de foco de este módulo

De "crear" a "sostener"

Todo lo anterior del curso resolvió cómo levantar infraestructura. La administración es el trabajo continuo, día tras día, para que siga funcionando bien, segura y dentro de presupuesto.

Visibilidad

Saber en todo momento qué está pasando: uso de recursos, errores, tráfico anómalo.

Control de acceso

Quién puede tocar qué — y poder demostrarlo ante una auditoría.

Costo bajo control

La elasticidad que tanto celebramos también puede disparar la factura sin que nadie lo note a tiempo.

No podés administrar lo que no medís

Monitoreo de recursos

Cómputo

Uso de CPU y RAM por instancia — la base para decidir si hace falta escalar o redimensionar.

Storage

Espacio disponible, IOPS, latencia de disco — un disco lleno tumba un servicio tan rápido como un CPU al 100%.

Red

Tráfico entrante/saliente, latencia, errores de conexión — clave para detectar tanto fallas como ataques.

En el laboratorio vamos a monitorear estos tres ejes con herramientas de línea de comandos simples — la misma lógica que usa cualquier plataforma de monitoreo profesional (Prometheus, Datadog, CloudWatch), solo que a mano.

Quién puede hacer qué

Gestión de usuarios y accesos

Principio de mínimo privilegio

Cada persona o servicio tiene exactamente el acceso que necesita — ni más, ni "por si acaso".

RBAC (control por roles)

En vez de dar permisos persona por persona, se definen roles (lectura, operador, admin) y se asignan usuarios a esos roles.

Auditoría

Registro de quién hizo qué y cuándo — imprescindible cuando algo sale mal y hay que reconstruir la secuencia de eventos.

La tarea menos glamorosa, la más crítica

Parcheo y actualizaciones

La mayoría de los incidentes de seguridad no explotan vulnerabilidades desconocidas — explotan vulnerabilidades conocidas y no parcheadas. Mantener el software actualizado es, en la práctica, una de las medidas de seguridad más efectivas que existen.

Ventanas de mantenimiento

Horarios planificados donde se aplican actualizaciones con el menor impacto posible en el servicio.

Automatización

Actualizaciones de seguridad automáticas para no depender de que alguien se acuerde de hacerlo a mano cada semana.

La elasticidad tiene un precio

Control de costos

Tagging

Etiquetar cada recurso por proyecto/equipo/ambiente, para saber después quién gastó qué.

Rightsizing

Revisar periódicamente si el flavor elegido sigue siendo el correcto, o si se está pagando de más por recursos que no se usan.

Alertas de presupuesto

Avisos automáticos antes de que el gasto se salga de control, no una sorpresa a fin de mes.

Administrar sin repetir manualmente cada paso

Infrastructure as Code (IaC)

En vez de crear y configurar recursos a mano (como hicimos en los laboratorios), la infraestructura se describe en archivos de texto versionables — y una herramienta se encarga de aplicarlos.

Herramientas típicas

Terraform (multi-proveedor), Ansible (configuración), CloudFormation (AWS nativo).

Ventaja clave

El estado de la infraestructura queda en control de versiones — se puede revisar, revertir y auditar como cualquier código.

Reproducibilidad

El mismo archivo levanta un entorno idéntico las veces que haga falta — adiós a "en mi servidor funcionaba".
