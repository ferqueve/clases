Antes de tocar comandos

¿Qué es una máquina virtual (VM)?

Una VM es una computadora simulada por software: tiene su propio "CPU" virtual, su propia RAM, su propio disco y su propia placa de red — pero todo corre como un programa dentro de una máquina física real. El sistema operativo instalado adentro no distingue si está en hardware real o virtualizado.

Aislamiento

Cada VM está separada de las demás, aunque compartan el mismo hardware físico por debajo.

Recursos asignados

La cantidad de CPU/RAM/disco que le damos es exactamente la que definimos — eso es, otra vez, un "flavor".

Portabilidad

Una VM se puede copiar, clonar o mover como si fuera un archivo, porque en el fondo lo es: un disco virtual + una configuración.

La pieza que hace todo esto posible

¿Qué es un hipervisor?

El hipervisor es el software que crea y administra máquinas virtuales, repartiendo el hardware físico real entre ellas. Hay dos tipos:

Tipo 1 — Bare-metal

Se instala directamente sobre el hardware, sin sistema operativo debajo. Ejemplos: Proxmox VE, VMware ESXi. Más eficiente — es lo que vamos a usar hoy.

Tipo 2 — Hosted

Se instala como un programa más, arriba de un sistema operativo ya existente. Ejemplos: VirtualBox, VMware Workstation. Más simple de instalar, algo menos eficiente.

Proxmox VE es el hipervisor — no es "un programa que instalás en Windows". Cuando lo instalamos, se convierte en el sistema operativo completo de ese servidor.
Las tres siglas que vamos a usar todo el laboratorio

QEMU, KVM y qm: quién hace qué

QEMU

El emulador de hardware: es el programa que efectivamente "dibuja" el CPU, la placa de red y el disco virtual que ve cada VM.

KVM

Un módulo del kernel de Linux que le da a QEMU acceso directo al hardware real (aceleración por hardware), para que la VM corra casi a la velocidad de una máquina física.

qm

El comando de Proxmox que usamos nosotros. Traduce "qm create", "qm start", etc. en lo que QEMU/KVM necesitan por detrás.

Analogía: QEMU/KVM es el motor del auto. qm es el volante y los pedales. Nosotros manejamos con qm — no necesitamos saber armar el motor para conducir.
Antes de empezar

Requisitos del laboratorio

Hardware/VM anfitriona

Mínimo 4 vCPU, 8GB RAM y 40GB de disco. Puede ser una VM anidada en VirtualBox si no hay hardware físico disponible.

ISO de Proxmox VE

Descargar la última versión estable desde el sitio oficial de Proxmox.

Red

Una interfaz con salida a internet para descargar plantillas y actualizaciones.

Si van a anidar Proxmox dentro de VirtualBox/VMware, hay que habilitar virtualización anidada (nested virtualization) en la VM anfitriona — si no, las VMs internas no van a bootear.

Instalación

Primeros pasos en la interfaz web

Datacenter

La vista raíz: agrupa todos los nodos, storages y permisos del cluster.

Nodo

El concepto central de hoy

Armando "flavors" propios

Proxmox no trae un catálogo cerrado de flavors como AWS o Azure — nosotros los definimos como plantillas de VM con un perfil fijo de vCPU/RAM/disco. Vamos a crear tres: small, medium y large.

flavor-small

1 vCPU · 1GB RAM · 8GB disco — para servicios livianos.

flavor-medium

2 vCPU · 2GB RAM · 16GB disco — uso general.

flavor-large

4 vCPU · 4GB RAM · 32GB disco — cargas más pesadas.

 crear la plantilla base (VM ID 9000)
qm create 9000 --name plantilla-ubuntu --memory 1024 --cores 1 \
  --net0 virtio,bridge=vmbr0 --scsihw virtio-scsi-pci \
  --scsi0 local-lvm:8 --ide2 local:iso/ubuntu-server.iso,media=cdrom \
  --boot order=ide2 --ostype l26

# Instalar el SO en la 9000 y luego convertirla en plantilla:
qm template 9000
Desglosando el comando: 9000 es el ID que le ponemos a esta VM (número libre a elección). --memory 1024 = 1GB de RAM. --cores 1 = 1 vCPU. --scsi0 local-lvm:8 = un disco de 8GB. --ide2 ...iso,media=cdrom = "insertamos" el CD virtual con el instalador de Ubuntu, igual que insertarías un pendrive booteable en una PC física.

Paso 3 · Clustering

Sumando un segundo nodo

Un cluster de Proxmox permite mover VMs entre servidores físicos. Se arma uniendo un nodo nuevo al cluster existente.

 en el nodo1 (crea el cluster)
pvecm create mi-cluster
 en el nodo2 (se une)
pvecm add IP-DEL-NODO1

# Verificar el estado del cluster desde cualquier nodo:
pvecm status
