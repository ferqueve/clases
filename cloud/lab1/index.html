VirtualBox CLI: VBoxManage Flavors propios
Antes de tocar comandos

¿Qué es una máquina virtual (VM)?

Una VM es una computadora simulada por software: tiene su propio "CPU" virtual, su propia RAM, su propio disco y su propia placa de red — pero todo corre como un programa dentro de una máquina física real.

Aislamiento

Cada VM está separada de las demás, aunque compartan el mismo hardware físico por debajo.

Recursos asignados

La cantidad de CPU/RAM/disco que le damos es exactamente la que definimos — eso es, otra vez, un "flavor".

Portabilidad

Una VM se puede copiar, clonar o exportar como si fuera un archivo, porque en el fondo lo es.

La pieza que hace todo esto posible

Hipervisor Tipo 2: por qué usamos VirtualBox

A diferencia de un hipervisor Tipo 1 (bare-metal, como Proxmox o ESXi, que reemplaza el sistema operativo del servidor), VirtualBox es Tipo 2 (hosted): se instala como un programa más, arriba de Windows, macOS o Linux.

Por qué lo elegimos para este laboratorio

No necesita virtualización anidada, no requiere una máquina dedicada, y corre directo en la notebook de cada estudiante — evita los problemas de compatibilidad que tuvimos con Proxmox.

El trade-off

Al compartir recursos con el sistema operativo anfitrión, el rendimiento es algo menor que un hipervisor bare-metal — aceptable para un entorno de laboratorio.

La CLI que vamos a usar todo el laboratorio

VBoxManage

Todo lo que se puede hacer desde la interfaz gráfica de VirtualBox, también se puede hacer (más rápido y repetible) desde la terminal con VBoxManage.

 verificar instalación
VBoxManage --version
VBoxManage list vms
Analogía del laboratorio anterior: si QEMU/KVM es el motor y qm el volante en Proxmox, acá VBoxManage cumple el mismo rol de "volante" para VirtualBox.

El concepto central de hoy

Armando "flavors" con VBoxManage

Igual que en Proxmox, VirtualBox no trae un catálogo cerrado de flavors — los definimos nosotros al crear la VM, fijando CPU, RAM y disco por línea de comandos.

 crear una carpeta de trabajo (una sola vez)
mkdir lab-vms
cd lab-vms
 crear una VM con flavor "small"
VBoxManage createvm --name "flavor-small" --ostype Ubuntu_64 --register
VBoxManage modifyvm "flavor-small" --cpus 1 --memory 1024
VBoxManage createhd --filename flavor-small.vdi --size 8192
VBoxManage storagectl "flavor-small" --name "SATA" --add sata
VBoxManage storageattach "flavor-small" --storagectl "SATA" --port 0 --device 0 \
  --type hdd --medium flavor-small.vdi
Desglosando: createvm registra la VM. modifyvm --cpus --memory define el flavor (1 vCPU, 1GB RAM). createhd crea el disco virtual (8192 = 8GB) en la carpeta donde estás parado — por eso creamos lab-vms primero, en vez de usar rutas con ~ o espacios escapados que en Windows no se interpretan igual que en Linux/macOS. Las líneas de storagectl/storageattach "conectan" ese disco a la VM, igual que enchufarías un disco físico.

Paso siguiente

Clonar una VM

En vez de repetir todos los pasos de creación, clonamos una VM ya armada — la forma más rápida de reproducir un flavor.

 clonar
VBoxManage clonevm "flavor-small" --name "web-01" --register
Portabilidad: la alternativa a la migración en vivo

Exportar e importar (OVA)

VirtualBox no tiene clustering ni migración en vivo como Proxmox — es un hipervisor de escritorio, no de servidor. Lo que sí tiene es exportar/importar una VM completa como un único archivo portable (formato OVA), para llevarla a otra máquina.

 exportar
VBoxManage export "flavor-small" --output flavor-small.ova
 importar (en otra máquina)
VBoxManage import flavor-small.ova
