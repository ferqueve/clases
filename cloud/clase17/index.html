Concepto · bloque

Tres formas de guardar datos en la nube

TipoCómo se accedeEjemploMódulo
BloqueComo un disco crudo: el sistema operativo lo formatea y lo montaEBS, Cinder, disco virtual de VirtualBox2
ArchivosCarpetas compartidas por red entre varias máquinasEFS, NFS, Samba—
ObjetosPor API HTTP, un objeto entero por vezS3, Swift, MinIO3

Bloque es la base de las otras dos. Detrás de un servidor de archivos o de una base de datos hay, casi siempre, un volumen de bloque.

Concepto · volumen

Un volumen es un disco que vive fuera de la instancia

instancia web-a
red de almacenamiento del proveedor · zona us-east-1a
/dev/sda1 · raízvol-0a1 · 8 GiB
/dev/sdf · datosvol-0b2 · 20 GiB

Para la instancia parece un disco conectado por cable. En realidad está en servidores de almacenamiento, al otro lado de una red.

analogía

Es un pendrive que se conecta y se desconecta. La instancia puede apagarse o desaparecer y el pendrive sigue con sus datos.

en cualquier nube

EBS en AWS, Cinder en OpenStack, Managed Disks en Azure y Persistent Disk en Google. El nombre cambia; la idea es la misma.

Concepto · tipos de volumen

Se elige por qué importa más: velocidad o costo

TipoSoportePensado paraRendimiento
gp3SSDUso general: sistemas, aplicaciones, bases de datos medianas3000 IOPS y 125 MiB/s de base, ampliables
io2SSDBases de datos críticas con mucha cargaIOPS provisionados a pedido, hasta decenas de miles
st1HDDLecturas grandes y seguidas: logs, big dataBuen caudal, pocas operaciones por segundo
sc1HDDDatos fríos que casi no se tocanEl más barato de todos

Los HDD no pueden ser volumen raíz. La regla práctica: gp3 salvo que haya un motivo medido para otra cosa.

Concepto · rendimiento

IOPS, caudal y latencia no son lo mismo

IOPS

Operaciones por segundo

Cuántas lecturas o escrituras pequeñas entran por segundo. Importa en bases de datos con muchas consultas chicas.

caudal (throughput)

MiB por segundo

Cuántos datos pasan por segundo. Importa al copiar archivos grandes o procesar logs enteros.

latencia

Milisegundos por operación

Cuánto tarda una sola operación. Importa cuando una aplicación espera cada respuesta antes de seguir.

Cuentas rápidas. Un volumen de 3000 IOPS que escribe bloques de 16 KiB mueve unos 47 MiB/s. Con bloques de 256 KiB, el límite pasa a ser el caudal y no los IOPS.

Concepto · ciclo de vida

Un volumen se crea, se adjunta y se suelta

creatingel proveedor reserva el espacio
availableexiste, pero ninguna instancia lo usa
in-useadjunto a una instancia
deletedborrado; los datos se pierden
Estado¿Se cobra?¿Qué lo cambia?
availableSí, por GB al mesattach-volume lo pasa a in-use
in-useSídetach-volume lo devuelve a available
deletedNoNo se puede deshacer

Un volumen suelto sigue costando. Es el error más común: borrar instancias y olvidar los volúmenes que quedaron en available.

Concepto · zona de disponibilidad

El volumen vive en una sola zona

us-east-1ainstancia web-a
vol-0b2 ✔ adjuntable
us-east-1binstancia web-b
vol-0b2 ✘ otra zona
región us-east-1dos centros de datos separados

Un volumen solo se adjunta a instancias de su misma zona. La razón es física: el disco y la instancia tienen que estar cerca para que la red entre ambos sea rápida.

para mover datos entre zonas

Se crea un snapshot y se restaura como volumen nuevo en la otra zona. Lo hacemos en la práctica 4.

Concepto · borrado

Qué pasa con los discos al terminar la instancia

volumen raíz

Se borra por defecto

La opción DeleteOnTermination viene en verdadero. Al terminar la instancia, su disco raíz desaparece con ella.

volúmenes adicionales

Se conservan por defecto

Los que se adjuntan después quedan en available. Los datos sobreviven, y también el cobro.

Dato importante para el diseño: los datos que no pueden perderse van en un volumen aparte, separado del sistema operativo. Se puede soltar de una instancia y adjuntar a otra.

Concepto · usar el disco

Adjuntar no alcanza: hay que formatear y montar

1 · adjuntar

La nube conecta el volumen. Dentro de la instancia aparece un dispositivo crudo, por ejemplo /dev/sdb, sin nada escrito.

2 · formatear

Se crea un sistema de archivos, como ext4 o xfs. Es lo que da forma a carpetas y archivos. Se hace una sola vez.

3 · montar

Se asocia el dispositivo a una carpeta, por ejemplo /datos. Lo que se guarda ahí cae en el volumen.

dentro de Linux
# ¿Qué discos ve el sistema?
lsblk
# Formatear (borra todo lo que tuviera)
sudo mkfs.ext4 /dev/sdb
# Montar
sudo mkdir /datos
sudo mount /dev/sdb /datos
df -h /datos

Formatear un volumen que ya tiene datos los destruye. Un volumen restaurado desde un snapshot ya viene formateado: solo se monta.

Concepto · montaje permanente

Que el montaje sobreviva al reinicio

/etc/fstab
# UUID del volumen
sudo blkid /dev/sdb

# Una línea por disco en /etc/fstab
UUID=3f1c-…  /datos  ext4  defaults,nofail  0  2

# Probar sin reiniciar
sudo umount /datos
sudo mount -a
por qué UUID

El nombre /dev/sdb puede cambiar entre reinicios. El UUID identifica al sistema de archivos y no cambia.

nofail

Si el volumen no está, el sistema arranca igual. Sin esta opción, una línea incorrecta en fstab puede dejar a la instancia sin arrancar.

Concepto · redimensionar

Un volumen puede crecer, no achicarse

1 · ampliar el volumen2 · ampliar la partición3 · ampliar el sistema de archivos
en la nube

modify-volume --size aumenta la capacidad, incluso con la instancia encendida. Después hay que esperar a que termine la optimización.

dentro de Linux

El sistema no usa el espacio nuevo hasta que se extienden la partición y el sistema de archivos.

dentro de Linux
# Si el disco tiene partición
sudo growpart /dev/xvda 1
# ext4: extender al tamaño del disco
sudo resize2fs /dev/xvda1
# xfs usa otro comando
sudo xfs_growfs /datos

Para achicar hay que crear un volumen más chico, copiar los datos y reemplazar el original.

Concepto · snapshot

Un snapshot es una foto del volumen en un momento

Guarda el contenido del volumen en el instante en que se pide. El volumen sigue funcionando mientras se toma.

no es un volumen

No se puede adjuntar a una instancia ni montar. Se usa para crear volúmenes nuevos.

es regional

No depende de la zona: de un snapshot se puede crear un volumen en cualquier zona de la región.

flujo completo

vol-0b2 → create-snapshot → snap-01 → create-volume → vol-0c3 en otra zona o con otro tamaño

tamaño

Un volumen restaurado puede ser mayor que el original, nunca menor.

Concepto · incremental

Cada snapshot guarda solo lo que cambió

volumen · lunes
snapshot 1 guarda
martes cambian 2
snapshot 2 guarda
8 bloques + 2 bloques

El segundo snapshot guarda 2 bloques y apunta a los otros 6 del primero. Ocupa un cuarto del espacio.

pero cada uno es completo

Se puede borrar el snapshot 1 y el 2 sigue restaurando los 8 bloques: el proveedor conserva lo que haga falta.

Concepto · estrategia de respaldo

Snapshots y RPO: cada cuánto sacar la foto

En la Clase 3 vimos el RPO: cuántos datos se aceptan perder. Con snapshots, el RPO es el tiempo entre una foto y la siguiente.

FrecuenciaRPO
cada horahasta 1 hora de datos
diariahasta 24 horas
semanalhasta 7 días
automatizar

Con una política de ciclo de vida, el proveedor toma y borra snapshots solo, según una regla: por ejemplo diarios, conservando los últimos siete.

consistencia

Si una base de datos está escribiendo, el snapshot puede captar datos a medias. Para bases de datos, se detiene la escritura un instante o se usa su propia herramienta de respaldo.

Concepto · dos alternativas

Instance store frente a volúmenes

volumen de bloque

Persistente

  • Sobrevive a detener, terminar o fallar la instancia
  • Se puede ampliar y respaldar
  • Pasa por la red: algo más de latencia
instance store

Efímero

  • Es un disco físico del servidor donde corre la instancia
  • Muy rápido y sin costo aparte
  • Los datos se pierden al detener la instancia

Instance store sirve para cachés y archivos temporales. Nada que haya que conservar.

Práctica 1 · Una instancia y un volumen

PowerShell
# Preparar la terminal (si no lo hiciste ya)
$env:AWS_ENDPOINT_URL      = "http://localhost:4566"
$env:AWS_ACCESS_KEY_ID     = "test"
$env:AWS_SECRET_ACCESS_KEY = "test"
$env:AWS_DEFAULT_REGION    = "us-east-1"
mkdir modulo-bloque; cd modulo-bloque

# Una instancia para conectar los discos
$VM = aws ec2 run-instances `
  --image-id ami-amazonlinux2023 --instance-type t3.micro `
  --placement AvailabilityZone=us-east-1a `
  --tag-specifications "ResourceType=instance,Tags=[{Key=Name,Value=srv-1},{Key=Proyecto,Value=modulo-bloque}]" `
  --query "Instances[0].InstanceId" --output text

# Un volumen de datos de 8 GiB, tipo gp3
$VOL = aws ec2 create-volume `
  --availability-zone us-east-1a --size 8 --volume-type gp3 `
  --tag-specifications "ResourceType=volume,Tags=[{Key=Name,Value=datos-1},{Key=Proyecto,Value=modulo-bloque}]" `
  --query "VolumeId" --output text

# Estado (esperado: available)
aws ec2 describe-volumes --volume-ids $VOL `
  --query "Volumes[0].[VolumeId,Size,VolumeType,AvailabilityZone,State]" --output table
misma zona

La instancia y el volumen llevan us-east-1a. Es el requisito de la diapositiva 8.

etiqueta

Todo lleva Proyecto=modulo-bloque para borrar todo junto al final.

DocenteProbar antes de clase si Floci acepta --placement y qué estados devuelve. Si no lo acepta, quitar esa línea y mantener la zona del volumen igual a la que informa la instancia.

Práctica 2 · Adjuntar y soltar

PowerShell
# Adjuntar datos-1 a srv-1 como /dev/sdf
aws ec2 attach-volume --volume-id $VOL `
  --instance-id $VM --device /dev/sdf

# Ahora el estado es in-use y aparece el adjunto
aws ec2 describe-volumes --volume-ids $VOL `
  --query "Volumes[0].[State,Attachments[0].InstanceId,Attachments[0].Device]" --output table

# Soltarlo: vuelve a available y los datos siguen
aws ec2 detach-volume --volume-id $VOL
aws ec2 wait volume-available --volume-ids $VOL

# Y adjuntarlo de nuevo, para las prácticas que siguen
aws ec2 attach-volume --volume-id $VOL `
  --instance-id $VM --device /dev/sdf
/dev/sdf

Es el nombre que se le pide a la nube. Dentro de Linux puede aparecer como /dev/xvdf o /dev/nvme1n1.

detach antes de borrar

Un volumen in-use no se puede eliminar. Primero se suelta.

Práctica 3 · Sacar un snapshot

PowerShell
# La foto de datos-1, con etiquetas
$SNAP = aws ec2 create-snapshot --volume-id $VOL `
  --description "datos-1 lunes" `
  --tag-specifications "ResourceType=snapshot,Tags=[{Key=Name,Value=snap-lunes},{Key=Proyecto,Value=modulo-bloque}]" `
  --query "SnapshotId" --output text

# Esperar a que termine y ver el estado
aws ec2 wait snapshot-completed --snapshot-ids $SNAP
aws ec2 describe-snapshots --snapshot-ids $SNAP `
  --query "Snapshots[0].[SnapshotId,VolumeId,VolumeSize,State,Progress]" --output table
estados

El snapshot pasa de pending a completed. Con volúmenes grandes en AWS real puede tardar minutos u horas.

el volumen sigue en uso

No hizo falta soltarlo ni apagar la instancia para tomar la foto.

Práctica 4 · Restaurar en otra zona y ampliar

PowerShell
# Restaurar el snapshot en OTRA zona
$VOLB = aws ec2 create-volume --snapshot-id $SNAP `
  --availability-zone us-east-1b `
  --tag-specifications "ResourceType=volume,Tags=[{Key=Name,Value=datos-1-restaurado},{Key=Proyecto,Value=modulo-bloque}]" `
  --query "VolumeId" --output text

# Mismo tamaño que el original, zona distinta
aws ec2 describe-volumes --volume-ids $VOLB `
  --query "Volumes[0].[VolumeId,Size,AvailabilityZone,SnapshotId,State]" --output table

# Restaurar ampliando: de 8 a 16 GiB
aws ec2 create-volume --snapshot-id $SNAP `
  --availability-zone us-east-1a --size 16
la columna SnapshotId

Indica de qué foto nació el volumen. Es la trazabilidad entre un volumen y su origen.

sin --size

Si no se indica, el volumen nuevo hereda el tamaño del snapshot. Con --size se puede pedir uno mayor, nunca menor.

Práctica 6 · Agregar un disco a la VM y montarlo

PowerShell · con la VM apagada
# Nombre y controladora de tu VM
VBoxManage list vms
VBoxManage showvminfo "ubuntu-server" | findstr /i "storage"

# Crear un disco de 2 GiB (en una carpeta simple)
mkdir C:\vms-disco; cd C:\vms-disco
VBoxManage createmedium disk --filename datos.vdi --size 2048

# Conectarlo (cambiá el nombre de la VM y de la controladora)
VBoxManage storageattach "ubuntu-server" --storagectl "SATA Controller" `
  --port 1 --device 0 --type hdd --medium C:\vms-disco\datos.vdi
Dentro de Ubuntu
lsblk
sudo mkfs.ext4 /dev/sdb
sudo mkdir /datos
sudo mount /dev/sdb /datos
echo "hola bloque" | sudo tee /datos/prueba.txt
df -h /datos
sudo blkid /dev/sdb
# Agregar la línea de UUID a /etc/fstab, y probar:
sudo umount /datos && sudo mount -a && cat /datos/prueba.txt
¿qué disco es?

El disco de 2 GiB que aparece en lsblk sin partición ni punto de montaje es el nuevo. Probablemente sdb.

cuidado

No formatear sda: es el disco del sistema operativo.

el mismo ciclo

Es lo que haría la instancia con un volumen adjunto: aparece crudo, se formatea, se monta y se guarda en fstab.

Limpieza

Borrar todo lo del módulo

PowerShell
# Instancias del módulo
$INST = (aws ec2 describe-instances `
  --filters "Name=tag:Proyecto,Values=modulo-bloque" "Name=instance-state-name,Values=pending,running,stopping,stopped" `
  --query "Reservations[].Instances[].InstanceId" --output text) -split "\s+"
aws ec2 terminate-instances --instance-ids $INST
aws ec2 wait instance-terminated --instance-ids $INST

# Volúmenes que quedaron en available (los adicionales no se borran solos)
$VOLS = (aws ec2 describe-volumes `
  --filters "Name=tag:Proyecto,Values=modulo-bloque" `
  --query "Volumes[].VolumeId" --output text) -split "\s+"
$VOLS | ForEach-Object { aws ec2 delete-volume --volume-id $_ }

# Snapshots del módulo
(aws ec2 describe-snapshots --owner-ids self `
  --filters "Name=tag:Proyecto,Values=modulo-bloque" `
  --query "Snapshots[].SnapshotId" --output text) -split "\s+" |
  ForEach-Object { aws ec2 delete-snapshot --snapshot-id $_ }

Se borran primero las instancias, después los volúmenes y al final los snapshots. Si un volumen se niega a borrarse, todavía está in-use: soltalo con detach-volume.
