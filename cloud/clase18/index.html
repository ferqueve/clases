Concepto · anatomía

Bucket, clave y objeto

la dirección de un objeto
s3://objetos-4821/reportes/2026/enero.txt
bucket

objetos-4821

El contenedor. Su nombre es único en todo el mundo, de 3 a 63 caracteres en minúscula. Pertenece a una región.

clave (key)

reportes/2026/enero.txt

El nombre completo del objeto dentro del bucket. Puede tener hasta 1024 bytes.

objeto

contenido + metadatos

Los datos, de 0 bytes a 5 TiB, más información: tipo de contenido, fecha, ETag y los metadatos propios que quieras agregar.

Concepto · espacio plano

Las carpetas no existen

Un bucket es una lista plana de claves. La barra / es un carácter más del nombre. Las consolas la muestran como carpeta porque agrupan por prefijo.

consecuencia

Renombrar una carpeta no existe: hay que copiar cada objeto con su clave nueva y borrar el original.

tres objetos, cero carpetas
reportes/2026/enero.txt
reportes/2026/febrero.txt
reportes/2025/diciembre.txt

# prefijo  reportes/2026/  →  2 objetos
# delimitador /  →  "subcarpetas" 2025/ y 2026/

Listar por prefijo y por delimitador es lo que simula el árbol de carpetas. Lo hacemos en la práctica 2.

Concepto · operaciones

Un bucket se maneja con pocas operaciones

OperaciónHTTPComando
Guardar un objetoPUTaws s3 cp archivo s3://bucket/clave
Leer un objetoGETaws s3 cp s3://bucket/clave destino
Ver solo los metadatosHEADaws s3api head-object
ListarGETaws s3 ls · list-objects-v2
BorrarDELETEaws s3 rm

Dos comandos en la CLI. aws s3 tiene atajos cómodos, como cp, ls y sync. aws s3api es la API completa, con todos los parámetros.

Concepto · durabilidad

Durabilidad no es disponibilidad

durabilidad

¿Se pierde el dato?

S3 Standard promete 99,999999999 % (once nueves). Guarda copias en al menos tres zonas. Con diez millones de objetos, se espera perder uno cada diez mil años.

disponibilidad

¿Puedo leerlo ahora?

S3 Standard promete 99,99 %: hasta unos 53 minutos al año sin poder acceder. El dato sigue ahí; el servicio no responde.

Conecta con el SLA y el RTO de la Clase 3. Un objeto es muy durable, pero una aplicación que lo necesita sigue dependiendo de la disponibilidad.

Concepto · versionado

Cada cambio guarda una versión

Con el versionado activado, subir un objeto con una clave existente no lo reemplaza: crea una versión nueva y conserva la anterior.

borrar

Un DELETE normal no elimina nada. Agrega un marcador de borrado como versión más nueva y el objeto deja de aparecer al listar.

recuperar

Se borra el marcador, o se lee una versión concreta con su versionId.

ClaveVersiónEstado
config.txt3f9…marcador de borrado (la más nueva)
config.txta07…v2
config.txtc41…v1

Protege de errores y de ransomware. Una vez activado, el versionado no se puede desactivar: solo suspender. Y cada versión se cobra como un objeto.

Concepto · ciclo de vida

Reglas que mueven y borran objetos solas

día 0el objeto nace en STANDARD
día 30pasa a STANDARD_IA
día 90pasa a GLACIER
día 365se elimina
filtro

La regla puede aplicarse a todo el bucket o solo a un prefijo, como logs/, o a objetos con una etiqueta.

también para versiones

Otra regla puede borrar versiones anteriores pasados N días, para que el versionado no crezca sin control.

Concepto · acceso

Un bucket nuevo es privado

política de identidad

Dice qué puede hacer un usuario o un rol. Se adjunta a la identidad. Módulo 6.

política de bucket

Dice quién puede tocar este bucket. Se adjunta al bucket y puede dar acceso a otras cuentas o al público.

bloqueo de acceso público

Un interruptor de seguridad por encima de las políticas. Está activo por defecto en los buckets nuevos.

política de bucket
{
  "Effect":    "Allow",
  "Principal": "*",
  "Action":    "s3:GetObject",
  "Resource":  "arn:aws:s3:::mi-bucket/publico/*"
}

Quién, qué y sobre qué. Principal es quién, Action es qué puede hacer y Resource es sobre qué objetos. Esta política deja leer a cualquiera solo lo que esté bajo publico/.

Concepto · URL prefirmada

Compartir un objeto privado por tiempo limitado

Una URL prefirmada lleva en sus parámetros una firma hecha con tus credenciales. Quien la tenga puede leer ese objeto hasta que venza, sin tener cuenta.

vencimiento

Se indica en segundos. Con credenciales de un usuario IAM, el máximo es de siete días.

cuidado

La URL es la llave

Cualquiera que la reciba puede usarla, la haya pedido o no. Por eso se usan vencimientos cortos y no se publican en lugares abiertos.

Concepto · archivos grandes

Subida multiparte

Una sola operación PUT admite hasta 5 GiB. Para objetos más grandes, hasta 5 TiB, el archivo se parte y las partes se suben por separado.

ventajas
  • Las partes viajan en paralelo y la subida termina antes
  • Si una parte falla, se repite solo esa parte
  • Se puede pausar y retomar
límites

Cada parte de 5 MiB a 5 GiB y hasta 10 000 partes por objeto.

la CLI lo hace sola

aws s3 cp usa multiparte automáticamente con archivos grandes. Las partes sin completar se siguen cobrando: una regla de ciclo de vida puede abortarlas.

Práctica 1 · Crear un bucket y subir objetos

PowerShell
# Preparar la terminal (si no lo hiciste ya)
$env:AWS_ENDPOINT_URL      = "http://localhost:4566"
$env:AWS_ACCESS_KEY_ID     = "test"
$env:AWS_SECRET_ACCESS_KEY = "test"
$env:AWS_DEFAULT_REGION    = "us-east-1"
mkdir modulo-objetos; cd modulo-objetos

# El nombre del bucket debe ser único en el mundo
$B = "objetos-" + (Get-Random -Maximum 99999)
aws s3 mb s3://$B

# Un archivo de prueba y su subida
"Informe de enero" | Out-File informe.txt -Encoding ascii
aws s3 cp informe.txt s3://$B/informe.txt

# Lo mismo, con metadatos propios
aws s3 cp informe.txt s3://$B/informe-meta.txt --metadata autor=ana,area=finanzas

# Listar y mirar los metadatos
aws s3 ls s3://$B
aws s3api head-object --bucket $B --key informe-meta.txt
$B

Guarda el nombre del bucket en una variable. Anotá el valor: lo usás en todas las prácticas.

head-object

Devuelve el tamaño, el tipo de contenido, el ETag y, en Metadata, los valores que pusiste con --metadata.

¿y si el nombre ya existe?

El error BucketAlreadyExists indica que otro lo tiene. Cambiá el número.

Práctica 2 · Listar por prefijo y delimitador

PowerShell
# Todos los objetos, claves completas
aws s3api list-objects-v2 --bucket $B `
  --query "Contents[].Key" --output table

# Solo los de un prefijo
aws s3api list-objects-v2 --bucket $B --prefix reportes/2026/ `
  --query "Contents[].Key"

# "Carpetas" del primer nivel de reportes/
aws s3api list-objects-v2 --bucket $B `
  --prefix reportes/ --delimiter / `
  --query "CommonPrefixes[].Prefix"

# Sincronizar una carpeta completa
mkdir lote; "a" | Out-File lote/a.txt -Encoding ascii
aws s3 sync lote s3://$B/respaldo/
CommonPrefixes

Es lo que la consola muestra como carpetas: los prefijos distintos hasta el delimitador.

sync

Compara y sube solo lo que falta o cambió. Es la forma de respaldar una carpeta entera.

Práctica 3 · Versionado, borrado y recuperación

PowerShell
# Activar el versionado
aws s3api put-bucket-versioning --bucket $B `
  --versioning-configuration Status=Enabled
aws s3api get-bucket-versioning --bucket $B

# Dos versiones de la misma clave
"version 1" | Out-File config.txt -Encoding ascii
aws s3 cp config.txt s3://$B/config.txt
"version 2" | Out-File config.txt -Encoding ascii
aws s3 cp config.txt s3://$B/config.txt

aws s3api list-object-versions --bucket $B --prefix config.txt `
  --query "Versions[].[VersionId,IsLatest,LastModified]" --output table

# Borrar: solo agrega un marcador
aws s3 rm s3://$B/config.txt
aws s3 ls s3://$B/config.txt
aws s3api list-object-versions --bucket $B --prefix config.txt `
  --query "DeleteMarkers[].[Key,VersionId,IsLatest]" --output table
qué observar

Después del rm, ls no muestra el objeto, pero list-object-versions sigue mostrando las dos versiones y un marcador.

anotá los ID

Guardá el VersionId del marcador y el de la versión 1: los usás ahora para recuperar.

recuperar

Quitar el marcador devuelve la versión 2: aws s3api delete-object --bucket $B --key config.txt --version-id <id-del-marcador>

Práctica 4 · Compartir un objeto con una URL prefirmada

PowerShell
# URL válida por 5 minutos
$URL = aws s3 presign s3://$B/informe.txt --expires-in 300
$URL

# Leer el objeto como lo haría un navegador
(Invoke-WebRequest $URL -UseBasicParsing).Content

# La misma dirección, sin firma
Invoke-WebRequest "http://localhost:4566/$B/informe.txt" -UseBasicParsing
los parámetros de la URL

Buscá en la URL X-Amz-Expires, X-Amz-Date y X-Amz-Signature. Ahí viajan el vencimiento y la firma.

resultado esperado en AWS

Con la URL firmada se lee el contenido. Sin firma, el servicio responde 403 Forbidden.

DocenteProbá si Floci rechaza la URL sin firma. Los emuladores suelen devolver el objeto igual. Si pasa, presentalo como diferencia con AWS real y no como un error.

Práctica 5 · Política de bucket de lectura pública

PowerShell
# Estado inicial del bloqueo público
aws s3api get-public-access-block --bucket $B

# La política: solo lectura, solo bajo publico/
@"
{"Version":"2012-10-17","Statement":[{
  "Sid":"LecturaPublica","Effect":"Allow","Principal":"*",
  "Action":"s3:GetObject","Resource":"arn:aws:s3:::$B/publico/*"}]}
"@ | Out-File politica.json -Encoding ascii

# Permitir políticas públicas y adjuntar la nuestra
aws s3api put-public-access-block --bucket $B `
  --public-access-block-configuration BlockPublicPolicy=false
aws s3api put-bucket-policy --bucket $B --policy file://politica.json
aws s3api get-bucket-policy --bucket $B --query Policy --output text

# Un objeto bajo el prefijo público
aws s3 cp informe.txt s3://$B/publico/informe.txt
Invoke-WebRequest "http://localhost:4566/$B/publico/informe.txt" -UseBasicParsing
dos permisos hacen falta

La política da el permiso, pero el bloqueo de acceso público tiene que dejarla pasar. Con el bloqueo activo, put-bucket-policy de una política pública falla en AWS real.

solo publico/*

Lo que está fuera de ese prefijo, como informe.txt en la raíz, sigue privado.

En una cuenta real, nunca abras un bucket entero. Muchas filtraciones de datos fueron buckets con lectura pública por error.

Práctica 6 · Clase de almacenamiento y ciclo de vida

PowerShell
# Subir directamente a una clase más barata
aws s3 cp informe.txt s3://$B/logs/enero.log --storage-class STANDARD_IA
aws s3api head-object --bucket $B --key logs/enero.log `
  --query StorageClass

# Regla: logs/ a IA a los 30 días, a GLACIER a los 90, borrar al año
@'
{"Rules":[{"ID":"archivar-logs","Status":"Enabled",
 "Filter":{"Prefix":"logs/"},
 "Transitions":[{"Days":30,"StorageClass":"STANDARD_IA"},
                {"Days":90,"StorageClass":"GLACIER"}],
 "Expiration":{"Days":365}}]}
'@ | Out-File ciclo.json -Encoding ascii

aws s3api put-bucket-lifecycle-configuration --bucket $B `
  --lifecycle-configuration file://ciclo.json
aws s3api get-bucket-lifecycle-configuration --bucket $B
StorageClass

El valor de STANDARD no aparece en la respuesta: si falta, es STANDARD.

la regla no se ve en segundos

AWS aplica las reglas una vez por día. Acá comprobamos que se guardó; no esperamos a que se cumpla.

el filtro

Prefix: logs/ limita la regla a esos objetos. Lo de reportes/ queda sin tocar.

Limpieza

Vaciar y borrar el bucket

PowerShell
# Con versionado, rm --recursive no alcanza: hay que borrar cada versión
$v = aws s3api list-object-versions --bucket $B --output json | ConvertFrom-Json
foreach ($o in (@($v.Versions) + @($v.DeleteMarkers))) {
  if ($o) {
    aws s3api delete-object --bucket $B --key $o.Key --version-id $o.VersionId | Out-Null
  }
}

# Ahora sí: el bucket vacío se puede borrar
aws s3 rb s3://$B
aws s3 ls

Un bucket con objetos o versiones no se puede borrar. Si rb da error, quedó alguna versión o un marcador.
