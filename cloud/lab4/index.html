El día después del despliegue

Sobre la misma VM de Ubuntu Server que ya tienen andando, vamos a monitorear recursos, gestionar un usuario nuevo con permisos acotados, y automatizar una tarea de mantenimiento con cron.

Antes de empezar

Requisitos del laboratorio

Una VM con Ubuntu Server

Cualquiera de las que ya tienen andando (NextCloud, o una nueva de VirtualBox) — no hace falta una VM adicional.

Acceso por Putty/SSH

Vamos a trabajar conectados por terminal, igual que en el laboratorio de NextCloud.

Usuario con sudo

El usuario que crearon al instalar Ubuntu, con permisos de administrador.

Paso 1 · Monitoreo

Ver qué está pasando ahora mismo

 procesos y CPU/RAM en vivo
top
# salir con "q"
 memoria disponible
free -h
Ejercicio 1

Ver el uso de disco

Escribí el comando para ver el espacio usado y disponible en cada partición, en formato legible para humanos (MB/GB en vez de bytes).

Paso 2 · Usuarios y accesos

Crear un usuario con permisos acotados

Vamos a crear un usuario "operador" que pueda hacer tareas de mantenimiento (con sudo), pero sin ser el usuario principal del sistema — el principio de mínimo privilegio en la práctica.

 crear el usuario
sudo adduser operador
# va a pedir contraseña y algunos datos opcionales — con Enter se pueden dejar vacíos
Ejercicio 2

Darle permisos de sudo al nuevo usuario

Escribí el comando para agregar al usuario operador al grupo sudo (sin quitarlo de los grupos que ya tiene).

El flag -aG es clave: -a (append) agrega sin borrar los grupos actuales, -G indica que lo que sigue es una lista de grupos. Olvidar el -a es un error clásico que saca al usuario de todos sus otros grupos.
Verificación

Confirmar el cambio

 ver a qué grupos pertenece
groups operador

Si "sudo" aparece en la lista, el usuario ya puede ejecutar comandos administrativos anteponiendo sudo — recién ahí queda listo para tareas de mantenimiento.

Paso 3 · Automatización

Programar una tarea con cron

cron ejecuta comandos automáticamente en horarios programados — la forma más simple de automatizar mantenimiento sin depender de que alguien se acuerde de hacerlo a mano.

 abrir el editor de tareas programadas
sudo crontab -e
Formato de una línea de cron: minuto hora día mes día-semana comando. Cada campo acepta * como "cualquiera". Ejemplo: 0 3 * * * significa "todos los días a las 3:00 AM".
Ejercicio 3

Escribir la línea de cron

Escribí la línea completa de cron para ejecutar apt update todos los días a las 3:00 AM.

Verificación final

Confirmar que la tarea quedó programada

 listar las tareas de cron activas
sudo crontab -l
Entregable del laboratorio

  • Línea de cron programada y verificada con crontab -l
