Paso 1 · Crear la VPC

PowerShell
# Red privada con 65 536 direcciones
$VPC = aws ec2 create-vpc --cidr-block 10.0.0.0/16 `
  --query Vpc.VpcId --output text

# Ponerle nombre (etiqueta Name)
aws ec2 create-tags --resources $VPC `
  --tags Key=Name,Value=lab-vpc

# Verificar
$VPC
aws ec2 describe-vpcs --vpc-ids $VPC
qué es

La VPC es nuestra red aislada. Nadie más la ve, aunque comparta el mismo hardware físico.

--query y --output text

De toda la respuesta JSON nos quedamos solo con el ID, para guardarlo en una variable.

etiquetas

Las etiquetas (tags) ordenan los recursos y permiten filtrarlos y repartir costos.

Paso 1 · Subred pública y salida a internet

PowerShell
# Subred pública en la zona us-east-1a
$SUBNET = aws ec2 create-subnet --vpc-id $VPC `
  --cidr-block 10.0.1.0/24 --availability-zone us-east-1a `
  --query Subnet.SubnetId --output text

# Internet gateway: la puerta de la VPC hacia internet
$IGW = aws ec2 create-internet-gateway `
  --query InternetGateway.InternetGatewayId --output text
aws ec2 attach-internet-gateway --internet-gateway-id $IGW --vpc-id $VPC

# Tabla de rutas: todo lo que no es local (0.0.0.0/0) sale por el gateway
$RTB = aws ec2 create-route-table --vpc-id $VPC `
  --query RouteTable.RouteTableId --output text
aws ec2 create-route --route-table-id $RTB `
  --destination-cidr-block 0.0.0.0/0 --gateway-id $IGW
aws ec2 associate-route-table --route-table-id $RTB --subnet-id $SUBNET

Diferencia con AWS real: Floci guarda las rutas y el gateway, pero no enruta paquetes de verdad. En AWS, sin estos tres comandos la subred no tendría salida a internet: es lo que la convierte en pública.

Paso 2 · Security group y par de claves

PowerShell
# Firewall para los servidores web
$SG = aws ec2 create-security-group `
  --group-name lab-web --description "Servidores web" `
  --vpc-id $VPC --query GroupId --output text

# Permitir HTTP desde cualquier origen
aws ec2 authorize-security-group-ingress --group-id $SG `
  --protocol tcp --port 80 --cidr 0.0.0.0/0

# Par de claves para SSH
aws ec2 create-key-pair --key-name lab-key `
  --query KeyMaterial --output text |
  Out-File -Encoding ascii lab-key.pem

# Ver las reglas
aws ec2 describe-security-groups --group-ids $SG
regla de entrada

Protocolo + puerto + origen. 0.0.0.0/0 significa “cualquier dirección”.

todo lo demás, cerrado

Un security group nuevo rechaza toda entrada hasta que se agrega una regla.

en Floci

Cada puerto TCP abierto se publica en tu máquina, en el rango 30000–30999.

Paso 3 · El script de arranque

web.sh (en la carpeta lab-iaas)
#!/bin/bash
dnf install -y nginx

# Preguntarle al servicio de metadatos quién soy
ID=$(curl -s http://169.254.169.254/latest/meta-data/instance-id)
IP=$(curl -s http://169.254.169.254/latest/meta-data/local-ipv4)

cat > /usr/share/nginx/html/index.html <<EOF
<h1>Servidor $ID</h1>
<p>IP privada: $IP</p>
EOF

nginx
user data

Corre una sola vez, en el primer arranque. Así cada servidor nace configurado sin que nadie entre a instalar nada.

metadatos

Cada servidor muestra su propio ID e IP. Con eso vamos a distinguir las dos instancias en el navegador.

Guardar con fin de línea LF. En VS Code se cambia abajo a la derecha (CRLF → LF). Con CRLF, Linux no reconoce la primera línea y el script no corre.

Paso 3 · Lanzar dos servidores

PowerShell
aws ec2 run-instances `
  --image-id ami-amazonlinux2023 `
  --instance-type t2.micro `
  --count 2 `
  --subnet-id $SUBNET `
  --security-group-ids $SG `
  --key-name lab-key `
  --user-data file://web.sh `
  --tag-specifications "ResourceType=instance,Tags=[{Key=Name,Value=web},{Key=Proyecto,Value=lab-iaas}]"

# Guardar los dos IDs en una lista
$IDS = (aws ec2 describe-instances `
  --filters "Name=tag:Proyecto,Values=lab-iaas" `
  --query "Reservations[].Instances[].InstanceId" --output text) -split "\s+"
$WEB1 = $IDS[0]

# Ver ID, IP privada, tipo y estado en una tabla
aws ec2 describe-instances --instance-ids $IDS `
  --query "Reservations[].Instances[].[InstanceId,PrivateIpAddress,InstanceType,State.Name]" `
  --output table

--count 2 crea dos instancias idénticas en una sola llamada. Las etiquetas se aplican a las dos.

Paso 4 · Un disco de bloque

PowerShell
# Volumen de 5 GiB en la misma zona que la subred
$VOL = aws ec2 create-volume --size 5 `
  --volume-type gp3 --availability-zone us-east-1a `
  --query VolumeId --output text

# Conectarlo a web-1 como /dev/sdf
aws ec2 attach-volume --volume-id $VOL `
  --instance-id $WEB1 --device /dev/sdf

# Verificar estado y a quién está conectado
aws ec2 describe-volumes --volume-ids $VOL `
  --query "Volumes[0].[Size,State,Attachments[0].InstanceId]"
misma zona

Un volumen solo se conecta a instancias de su zona de disponibilidad. Por eso usamos us-east-1a en los dos.

persistente

El volumen sobrevive aunque la instancia se apague o se borre. Es el lugar para los datos que importan.

en Floci

Según la configuración de Docker, el disco aparece dentro de la instancia o queda registrado solo en la API. Para este laboratorio alcanza con verlo en estado in-use.

Paso 5 · Escalado vertical

web-1 necesita más memoria. Para cambiar el tipo de instancia hay que apagarla primero.

PowerShell
# 1. Apagar y esperar
aws ec2 stop-instances --instance-ids $WEB1
aws ec2 wait instance-stopped --instance-ids $WEB1

# 2. Cambiar de t2.micro (1 GiB) a t3.small (2 GiB)
aws ec2 modify-instance-attribute --instance-id $WEB1 `
  --instance-type Value=t3.small

# 3. Encender y comprobar
aws ec2 start-instances --instance-ids $WEB1
aws ec2 describe-instances --instance-ids $WEB1 `
  --query "Reservations[0].Instances[0].[InstanceType,State.Name]"
vertical vs horizontal

En el paso 3 sumamos servidores. Acá agrandamos uno. Escalar verticalmente exige apagar: hay un corte de servicio.

nginx no vuelve solo

El user data corre solo en el primer arranque, y lo lanzamos a mano. Hay que iniciarlo de nuevo: docker ps para ubicar el contenedor y docker exec <id> nginx.

puerto publicado

Al apagar, Floci quita la publicación del puerto. Para restaurarla, revocar y volver a autorizar la regla del puerto 80.

Paso 5 · Volver a publicar web-1

PowerShell
# Iniciar nginx dentro de la instancia
docker ps                         # ubicar el contenedor de web-1
docker exec <id-del-contenedor> nginx

# Republicar el puerto 80
aws ec2 revoke-security-group-ingress --group-id $SG `
  --protocol tcp --port 80 --cidr 0.0.0.0/0
aws ec2 authorize-security-group-ingress --group-id $SG `
  --protocol tcp --port 80 --cidr 0.0.0.0/0

# Buscar el nuevo puerto en los logs y probar
floci logs

En un servidor real, nginx se registra como servicio (systemctl enable nginx) y arranca solo después de cada reinicio. Nuestro contenedor no tiene systemd, por eso lo hacemos a mano.

Paso 6 · Desarmar todo, en orden

PowerShell
# 1. Esperar a que las instancias terminen y borrar el volumen
aws ec2 wait instance-terminated --instance-ids $IDS
aws ec2 delete-volume --volume-id $VOL

# 2. Firewall y clave
aws ec2 delete-security-group --group-id $SG
aws ec2 delete-key-pair --key-name lab-key

# 3. Subredes de la VPC (la pública y la privada)
$SUBNETS = (aws ec2 describe-subnets --filters "Name=vpc-id,Values=$VPC" `
  --query "Subnets[].SubnetId" --output text) -split "\s+"
foreach ($s in $SUBNETS) { aws ec2 delete-subnet --subnet-id $s }

# 4. Rutas, gateway y VPC
aws ec2 delete-route-table --route-table-id $RTB
aws ec2 detach-internet-gateway --internet-gateway-id $IGW --vpc-id $VPC
aws ec2 delete-internet-gateway --internet-gateway-id $IGW
aws ec2 delete-vpc --vpc-id $VPC

# 5. Bucket con su contenido
aws s3 rb s3://lab-iaas-backups --force

El orden importa: una VPC no se puede borrar mientras tenga subredes, security groups propios o un gateway conectado. El error se llama DependencyViolation.
