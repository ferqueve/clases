01 · Punto de partida

Cuando decimos “guardar en la nube”… ¿qué ocurre realmente?

Cliente

PC, navegador, móvil o aplicación de escritorio.

Red

Transporta las solicitudes mediante HTTP/HTTPS, WebDAV y otros protocolos.

Servidor

Autentica, procesa, almacena metadatos y entrega los archivos.

La nube no elimina los servidores: cambia dónde están, quién los administra y cómo accedemos a ellos.

02 · ¿Qué es Nextcloud?

Una nube privada que tú puedes administrar

Nextcloud es una plataforma open source y autoalojable para sincronizar, compartir y colaborar con archivos desde interfaces web, móviles y de escritorio.

El punto conceptual clave para Cloud Computing es el control de la infraestructura y de los datos: la organización decide dónde vive el servicio.

Podemos desplegarlo on-premises, en una VM, VPS o infraestructura de un proveedor cloud.

Fuente: Nextcloud — plataforma oficial y Nextcloud Files.

07 · Protocolos

No todo ocurre “por magia”

HTTPS

Protege el tráfico entre cliente y servidor cuando configuramos TLS correctamente.

WebDAV

Permite trabajar con archivos remotos utilizando estándares web y facilita integración con distintos clientes.

APIs e integraciones

Nextcloud se integra con otras herramientas y servicios mediante interfaces programáticas y aplicaciones.

Cloud = servicios comunicándose por red.

08 · Seguridad

Controlar el servidor también significa asumir responsabilidades

Identidad

Usuarios, grupos, contraseñas, MFA y permisos.

Transporte

HTTPS/TLS para evitar enviar credenciales y datos en claro.

Hardening

Actualizaciones, firewall, mínimos privilegios y revisión de configuración.

Datos

Proteger tanto la base como el directorio de datos.

Backup

Un servicio cloud sin copia recuperable no está realmente protegido.

Logs

Registrar actividad ayuda a diagnosticar errores e investigar incidentes.

10 · Preparando el laboratorio

La documentación oficial estable incluye un ejemplo de instalación para Ubuntu 24.04 LTS con Apache y MariaDB.

11 · Antes de instalar

Checklist del servidor

# Identidad del servidor
hostnamectl

# IP
ip a

# Ruta y gateway
ip route

# DNS / conectividad
ping -c 3 1.1.1.1
ping -c 3 nextcloud.com
# Actualizar índices y paquetes
sudo apt update
sudo apt upgrade -y

# Espacio disponible
df -h

# Memoria
free -h

# Puertos escuchando
sudo ss -tulpn

Antes de culpar a Nextcloud, debemos saber si el servidor tiene red, DNS, espacio, memoria y paquetes actualizados.

13 · Base de datos

Crear una base y un usuario dedicados

sudo mariadb

CREATE DATABASE nextcloud CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;

CREATE USER 'nextcloud'@'localhost'
IDENTIFIED BY 'CAMBIAR_ESTA_CLAVE';

GRANT ALL PRIVILEGES ON nextcloud.* TO 'nextcloud'@'localhost';

FLUSH PRIVILEGES;
EXIT;
Principio: la aplicación no necesita utilizar la cuenta administrativa global de MariaDB.
14 · Aplicación

Descargar y ubicar Nextcloud

Para el laboratorio, la idea será obtener la versión indicada por el docente/documentación oficial y desplegarla bajo el directorio servido por Apache.

# Ejemplo conceptual
cd /tmp
# descargar paquete oficial de Nextcloud
# verificar el paquete si corresponde
# descomprimir
# mover a /var/www/nextcloud

sudo chown -R www-data:www-data /var/www/nextcloud
No memorices URLs o versiones. En administración de sistemas es mejor verificar la documentación actual que copiar comandos antiguos de Internet.
15 · Apache

Publicar la aplicación

<VirtualHost *:80>
    ServerName nextcloud.lab

    DocumentRoot /var/www/nextcloud

    <Directory /var/www/nextcloud/>
        Require all granted
        AllowOverride All
        Options FollowSymLinks MultiViews
    </Directory>
</VirtualHost>
sudo a2enmod rewrite headers env dir mime
sudo a2ensite nextcloud.conf
sudo apache2ctl configtest
sudo systemctl reload apache2

En clase conviene revisar qué hace cada módulo y por qué ejecutamos configtest antes de recargar.

16 · Instalación web

El navegador completa el enlace entre capas

  1. Abrir la IP o nombre del servidor.
  2. Crear la cuenta administrativa de Nextcloud.
  3. Definir directorio de datos.
  4. Seleccionar MariaDB/MySQL.
  5. Ingresar usuario, contraseña, base y host.
  6. Finalizar la instalación.

Lo importante

En este punto Nextcloud ya puede comunicarse con la base, escribir en su almacenamiento y responder solicitudes web.

18 · Escalabilidad

La VM del laboratorio no es el final

En un entorno real, podemos separar responsabilidades:

  • Servidor web / PHP.
  • Base de datos dedicada.
  • Redis para locking/caché.
  • Almacenamiento externo u object storage según arquitectura.
  • Proxy inverso o balanceador.
  • Backups externos.
  • Monitoreo y observabilidad.
Lección cloud: primero desplegamos un sistema simple para comprenderlo; luego desacoplamos componentes para crecer.
