Concepto

¿Qué es Dokku?

Una plataforma como servicio extensible y de código abierto que se ejecuta en un único servidor de tu elección. Es una alternativa a Heroku que podés alojar vos mismo.

Despliegue por git push

Creás la aplicación al subir el código. No hace falta armar la imagen ni los contenedores a mano.

Dockerfile o buildpacks

Si tu proyecto tiene Dockerfile, lo usa. Si no, detecta el lenguaje automáticamente con buildpacks.

Enrutamiento automático

Con nginx dirige el tráfico web a los contenedores. También administra procesos en segundo plano y tareas cron.

La idea central. Vos entregás el código. Dokku se ocupa de construir, ejecutar y publicar. Es el modelo de responsabilidad compartida de PaaS, pero con el servidor en tus manos.
Concepto

Qué pasa cuando hacés git push

Cada paso lo hace Dokku por vos. Pulsá el botón para recorrerlos.

git pushEl código llega al servidor por SSH
DetectaDockerfile o lenguaje del proyecto
ConstruyeInstala dependencias y arma la imagen
EjecutaInicia contenedores desde esa imagen
Publicanginx enruta el tráfico web
Idea clave. Un nuevo git push repite el proceso y reemplaza la versión anterior. Desplegar es subir código, no operar servidores.
Concepto

Las piezas que Dokku orquesta

Dokku no reinventa nada: une herramientas conocidas.

Docker

Ejecuta cada aplicación en su propio contenedor, con las dependencias aisladas.

nginx

Recibe el tráfico y lo reparte según el dominio o el puerto de cada aplicación.

Buildpacks

Detectan el lenguaje y construyen la imagen sin que escribas un Dockerfile.

SSH y Git

El canal de despliegue. Tu clave pública identifica a quién puede subir código.

cron

Ejecuta tareas programadas de las aplicaciones.

Plugins

Extienden Dokku: bases de datos (PostgreSQL, MySQL, Redis), certificados HTTPS y más.

Heroku (PaaS comercial)El proveedorgit pushQuerés cero operación y aceptás pagar por ello
Dokku (PaaS propio)Vos, en un único servidorgit pushQuerés la experiencia de PaaS con costo y control propios

Límite a tener en cuenta. Dokku corre en un único servidor. No reparte la carga entre varias máquinas por sí solo. Si el servidor cae, las aplicaciones caen. Es excelente para equipos chicos, pruebas y enseñanza.
Instalación · antes de empezar

Requisitos mínimos

Ubuntu 20.04

Instalación limpia. Es la que corresponde a la versión 0.32.0 que vamos a instalar.

1 GB de RAM

Como mínimo. Las aplicaciones y la base de datos también consumen memoria.

30 GB de disco

Las imágenes de contenedores y los datos ocupan espacio rápido.

Convención del instructivo. Todos los comandos se ejecutan como root. Para pasar a root: sudo -i.
Si lo hacés en una máquina virtual. Usá una VM limpia o un clon de la VM base, sin Apache ni NextCloud: Dokku instala nginx y necesita el puerto 80. Conectala en modo puente (bridge) para que tu PC pueda llegar a su IP.
servidor Ubuntu
$ sudo -i
# lsb_release -ds    # comprobar que es Ubuntu 20.04
# free -h            # memoria disponible
# df -h /            # espacio en disco
Instalación · paso 1 de 3

Descargar e instalar Dokku

Descargamos el instalador de la versión estable y lo ejecutamos indicando la versión con DOKKU_TAG.

root@servidor
# wget -NP . https://dokku.com/install/v0.32.0/bootstrap.sh
# sudo DOKKU_TAG=v0.32.0 bash bootstrap.sh

Tarda de 5 a 10 minutos

Depende de la conexión a Internet. Descarga Docker, nginx y los componentes de Dokku.

Fijar la versión

Con DOKKU_TAG todos instalan la misma versión y los resultados son comparables.

verificar
# dokku version
# dokku version 0.32.0
Instalación · paso 2 de 3

La llave SSH: quién puede desplegar

Dokku identifica a quien sube el código por su clave pública. Generamos el par de claves y registramos la pública en Dokku.

root@servidor
# 1. Generar la clave (Enter a todo deja los valores por defecto)
# ssh-keygen

# 2. Asignarla al usuario "admin" de Dokku
# cat ~/.ssh/id_rsa.pub | sudo dokku ssh-keys:add admin

Qué queda registrado

El nombre admin es una etiqueta para esa clave dentro de Dokku. No es un usuario de Linux.

Si desplegás desde otra máquina

Generá el par de claves en esa máquina y agregá su clave pública al servidor. Con la clave del propio servidor solo podrías desplegar desde él.

Instalación · paso 3 de 3

El dominio global

Dokku necesita saber con qué nombre publicar las aplicaciones. Hay tres opciones: elegí una.

Cualquier dominio al que ya tengas acceso. Necesita un registro A o CNAME que apunte a la IP del servidor. El instructivo usa dokku.me como ejemplo.

root@servidor
# dokku domains:set-global dokku.me

Usamos la IP de la máquina virtual. Es la opción de la demo: no necesita dominio ni DNS.

root@servidor
# dokku domains:set-global 192.168.5.186

Cambiá la IP por la de tu servidor (ip a te la muestra). Al terminar el despliegue, Dokku informa la dirección y el puerto de la aplicación.

Con sslip.io obtenés subdominios como si tuvieras un dominio propio. Se logra agregando .sslip.io a la dirección IP.

root@servidor
# dokku domains:set-global 192.168.5.186.sslip.io
Para recordar. La instalación ya terminó. Tenés una plataforma lista para recibir aplicaciones.

Primer despliegue · paso 1 de 4

Traer el código y crear la aplicación

Usamos una aplicación de ejemplo de Heroku, escrita en Ruby. En la máquina de trabajo clonamos el repositorio. En el servidor Dokku creamos la aplicación.

máquina de trabajo
$ git clone https://github.com/heroku/ruby-getting-started
root@servidor Dokku
# dokku apps:create ruby-getting-started
Dos máquinas, un solo recorrido. En la demo ambas pueden ser la misma. Con dos máquinas, el git clone y el git push se hacen en tu PC y los comandos dokku en el servidor.
Esta aplicación necesita una base de datos. Dokku no trae ninguna por defecto. En el siguiente paso instalamos el plugin de PostgreSQL.
Primer despliegue · paso 2 de 4

Una base de datos como servicio

En PaaS los datos viven en un servicio de apoyo, separado de la aplicación. En Dokku se agrega con un plugin. Es la idea de «recurso conectable» de los 12 factores.

root@servidor Dokku
# 1. Instalar el plugin de PostgreSQL (requiere root)
# sudo dokku plugin:install https://github.com/dokku/dokku-postgres.git

# 2. Crear un servicio de PostgreSQL
# dokku postgres:create railsdatabase

Plugins oficiales

Hay plugins oficiales para otros almacenes de datos: MySQL, MongoDB, Redis y más. La lista completa está en el repositorio de Dokku.

Un servicio, un nombre

El servicio se llama railsdatabase. Ese nombre lo usamos para enlazarlo a la aplicación.

Primer despliegue · paso 3 de 4

Enlazar el servicio con la aplicación

Cada almacén de datos oficial ofrece un método de enlace (link) para vincularlo a una aplicación.

root@servidor Dokku
# dokku postgres:link railsdatabase ruby-getting-started

Qué hace el enlace

Le entrega a la aplicación los datos de conexión como una variable de entorno (DATABASE_URL). El código no lleva contraseñas escritas.

Reglas de vinculación

Un mismo servicio puede vincularse a varias aplicaciones. Cada aplicación admite un solo servicio de ese tipo.

Conexión con los 12 factores. Configuración en variables de entorno y servicios de apoyo conectables: dos principios que Dokku aplica solo.

Primer despliegue · paso 4 de 4

Desplegar: remote y push

Entramos a la carpeta del proyecto y agregamos un remote de Git que apunta a Dokku. La aplicación se crea sobre la marcha en el servidor.

máquina de trabajo
$ cd ruby-getting-started
$ git remote add dokku dokku@192.168.5.186:ruby-getting-started
$ git push dokku main

El usuario debe ser dokku

En la dirección dokku@IP:aplicación, el usuario del remote tiene que ser dokku. Con otro, el push falla.

La rama

El ejemplo usa main. Si tu repositorio usa master, subí esa rama.

Primer despliegue · resultado

Cómo leer la salida del push

Verás una serie de pasos que detectan el código y despliegan lo necesario. Al final, Dokku muestra la ruta y el puerto para entrar a la aplicación.

Dokku recibe el código por SSH y lo prepara para la construcción. Si falla aquí, revisá la clave SSH y el usuario del remote.

Detecta el lenguaje de la aplicación (acá, Ruby) o usa el Dockerfile. Instala las dependencias y arma la imagen. Es el paso más largo.

Inicia los contenedores con la imagen construida y verifica que respondan antes de enviarles tráfico.

nginx se configura para enrutar el tráfico. Dokku imprime la dirección de la aplicación: abrila en el navegador para comprobarla.

Operación · administrar aplicaciones

El día a día: aplicaciones y configuración

Los comandos dokku se ejecutan en el servidor. También podés lanzarlos desde tu PC por SSH: ssh dokku@IP apps:list.

ComandoPara qué sirve
dokku apps:listLista las aplicaciones del servidor
dokku apps:create nombreCrea una aplicación
dokku config:set app CLAVE=valorDefine una variable de entorno (y reinicia la app)
dokku config:show appMuestra las variables de la aplicación
dokku logs app -tSigue los logs en vivo (-t = tail)
dokku domains:add app dominioAgrega un dominio a la aplicación
dokku domains:report appMuestra los dominios configurados
Configuración fuera del código. Las contraseñas y direcciones se guardan con config:set, no en el repositorio. Es el principio III de los 12 factores.
Operación · procesos y escalado

Escalar, reiniciar y entrar al contenedor

root@servidor Dokku
# Ver procesos y su estado
# dokku ps:report ruby-getting-started

# Tener 2 procesos web
# dokku ps:scale ruby-getting-started web=2

# Reiniciar la aplicación
# dokku ps:restart ruby-getting-started
root@servidor Dokku
# Ejecutar un comando puntual en la app
# dokku run ruby-getting-started ls

# Abrir una terminal dentro del contenedor
# dokku enter ruby-getting-started

Escalado horizontal

Es el mismo concepto de los módulos de balanceo: más procesos iguales. Dokku los pone detrás de nginx.

Escalar tiene techo

Todos los procesos corren en el mismo servidor. Si la memoria se agota, más procesos no ayudan.

Operación · servicios y ciclo de vida

Servicios de datos, actualizaciones y bajas

Servicio PostgreSQL

# dokku postgres:list
# dokku postgres:info railsdatabase
# dokku postgres:logs railsdatabase
# dokku postgres:connect railsdatabase

Para ver los servicios, su estado y los logs, o conectarte con el cliente de PostgreSQL.

Actualizar y dar de baja

# Actualizar: cambiá el código y subilo de nuevo
$ git push dokku main

# Desenlazar y borrar (con cuidado)
# dokku postgres:unlink railsdatabase ruby-getting-started
# dokku apps:destroy ruby-getting-started

Cada git push es un nuevo despliegue. Borrar pide confirmación.

Antes de destruir. Borrar un servicio de datos elimina la información. En un entorno real se hacen respaldos antes de cualquier baja.
Operación · cuando algo falla

Problemas frecuentes

SíntomaCausa probableQué hacer
Permission denied (publickey)La clave pública no está registrada en DokkuRepetir ssh-keys:add con la clave de la máquina desde la que desplegás
El push falla de entradaEl usuario del remote no es dokkuCorregir con git remote set-url dokku dokku@IP:app
src refspec main does not matchLa rama no se llama mainSubir la rama real, por ejemplo git push dokku master
La app se despliega pero falla al abrirFalta enlazar la base de datosRevisar postgres:link y dokku logs app
No se llega a la dirección desde la PCLa VM no está en modo puente o el puerto está bloqueadoRevisar la red de la VM y la IP con ip a
La construcción se corta o va muy lentaPoca memoria o poco discoRevisar free -h y df -h
Primera herramienta de diagnóstico. Siempre empezá por dokku logs nombre-app. Es lo primero que se mira en una plataforma.
