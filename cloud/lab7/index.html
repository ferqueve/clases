Qué vamos a hacer

Operar una nube pequeña y dejar evidencia

Vas a hacer lo que hace un administrador de IaaS: crear instancias de distintos tamaños, conectarlas por red, guardar datos en un volumen y capturar una imagen. Todo desde una consola gráfica y desde la terminal.

por qué contenedores

Las máquinas virtuales nos dieron problemas en varias PC. Los contenedores corren con 8 GB de RAM y no necesitan virtualización anidada.

El aislamiento

  • Comparte el kernel con tu PC, sin kernel propio
  • No instala un sistema operativo completo
  • Arranca en segundos y pesa megabytes
  • Sin disco de arranque propio

Esta diferencia es el tema de la Clase 6 y del deck contenedor frente a máquina virtual. En el informe vas a explicarla con tus propias observaciones.

Paso 1 · Instalar la consola

PowerShell
# Verificar Docker
docker version

# Un volumen para que la consola guarde sus datos
docker volume create portainer_data

# La consola: un contenedor más
docker run -d --name portainer --restart=always `
  -p 9443:9443 -p 8000:8000 `
  -v /var/run/docker.sock:/var/run/docker.sock `
  -v portainer_data:/data `
  portainer/portainer-ce:lts

# ¿Está corriendo?
docker ps --filter "name=portainer"
el socket de Docker

La línea con docker.sock le da a Portainer acceso al motor de Docker. Así puede crear y administrar contenedores, igual que Horizon administra Nova.

si falla

Si el puerto 9443 está ocupado, cambiá el primer número, por ejemplo -p 9444:9443, y abrí esa dirección.

DocenteProbar esta instalación en Docker Desktop de Windows antes de clase. Si el montaje del socket da error, revisar que Docker Desktop use WSL 2.

Paso 2 · Los flavors del laboratorio

Un flavor fija cuánta CPU y memoria recibe una instancia. En Docker se logra con dos límites. Vamos a usar tres tamaños:

FlavorCPUMemoria
flavor-small0,25128 MB
flavor-medium0,5256 MB
flavor-large1512 MB
--memory

Tope de memoria RAM. Si la instancia lo supera, Docker la mata. Lo veremos en el desafío del paso 7.

--cpus

Fracción de CPU. 0.5 es la mitad de un núcleo.

igual que el módulo 1

Es la lógica de t2.micro, t3.small o m7i.large: elegir un tipo del catálogo, no pedir cualquier valor.

Paso 3 · Crear una instancia desde la terminal

PowerShell
# flavor-large: 1 CPU y 512 MB
docker run -d --name web-large --memory 512m --cpus 1 `
  -p 8083:80 nginx:alpine

# Los límites tal como los guarda Docker
docker inspect web-small web-large `
  --format "{{.Name}} memoria={{.HostConfig.Memory}} cpu={{.HostConfig.NanoCpus}}"

# Uso y límite de cada instancia
docker stats --no-stream `
  --format "table {{.Name}}\t{{.CPUPerc}}\t{{.MemUsage}}"
cómo leer inspect

La memoria se guarda en bytes: 536870912 es 512 MiB. La CPU se guarda en milmillonésimos de núcleo: 1000000000 es 1 núcleo.

cómo leer stats

La columna MEM USAGE muestra el uso actual, una barra y el límite. El límite de cada fila es su flavor.

Paso 4 · Conectar las instancias por red

Una red define quién puede hablar con quién. En una red creada por vos, las instancias se encuentran por nombre, sin conocer su IP. Es el equivalente a una subred privada.

# Conectar web-medium a la misma red
docker network connect red-lab web-medium

Paso 5 · Un volumen que sobrevive a la instancia

Lo que se escribe dentro de un contenedor se pierde si el contenedor se borra. Un volumen guarda datos aparte, como el volumen de bloque del módulo 2.

ejercicio 3

La instancia db-1 con el volumen datos-lab la creás en el ejercicio siguiente. Después usás este bloque.

Captura 5La salida del último comando mostrando el contenido de nota.txt con la instancia original ya borrada.
PowerShell · después del ejercicio 3
# Escribir un dato en el volumen
docker exec db-1 sh -c "echo 'dato importante' > /datos/nota.txt"

# Borrar la instancia: el volumen queda
docker rm -f db-1
docker volume ls --filter "name=datos-lab"

# Una instancia nueva lee el mismo dato
docker run --rm -v datos-lab:/datos alpine cat /datos/nota.txt

Paso 7 · Ciclo de vida y un desafío

PowerShell
# Apagar, ver el estado, encender y reiniciar
docker stop web-small
docker ps -a --filter "name=web" --format "table {{.Names}}\t{{.Status}}"
docker start web-small
docker restart web-small

# DESAFÍO (opcional): una instancia que se pasa de su flavor
docker run --name prueba-oom --memory 20m alpine tail /dev/zero
docker inspect prueba-oom --format "{{.State.OOMKilled}} {{.State.ExitCode}}"
en la consola

Mirá Containers en Portainer mientras apagás y encendés. El estado cambia entre running y exited.

el desafío

tail /dev/zero intenta guardar en memoria un flujo infinito. Al pasar los 20 MB del límite, Docker la mata. Se espera true 137.

Captura 7La lista de contenedores con web-small detenida y, después, otra con las instancias en running. Si hiciste el desafío, sumá el resultado de inspect.
DocenteProbar el desafío antes de clase: depende de cómo se comporte tail en la imagen. Si no termina rápido, cortarlo con Ctrl+C y presentarlo como opcional.
Limpieza

Dejar la PC como estaba

PowerShell
# Instancias del laboratorio
docker rm -f web-small web-medium web-large web-clon app-1 db-1 prueba-oom

# Red, volumen e imagen propios

# Comprobar
