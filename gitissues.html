¿Qué son los Issues en GitHub?

Los issues son una herramienta fundamental en GitHub para rastrear tareas, mejoras, bugs y cualquier tipo de trabajo relacionado con un proyecto.

Casos de uso principales:

  • Reportar bugs: Documentar errores encontrados en el código
  • Solicitar features: Proponer nuevas funcionalidades
  • Hacer preguntas: Consultas sobre el proyecto
  • Documentar tareas: Organizar el trabajo del equipo
  • Discusiones técnicas: Debatir sobre implementaciones

Beneficios:

  • Sistema centralizado de seguimiento
  • Facilita la colaboración del equipo
  • Historial completo de cambios
  • Integración con PRs y commits

Componentes de un Issue

Título

Descripción breve y clara del problema o tarea. Debe ser conciso pero informativo.

Descripción

Detalles completos usando Markdown: pasos para reproducir, capturas, código.

Labels

Etiquetas para categorizar: bug, enhancement, documentation, etc.

Assignees

Personas responsables de resolver el issue.

Milestone

Agrupación por versión o sprint del proyecto.

Comments

Discusión y actualizaciones sobre el progreso.

Método 1: Interfaz Web

La forma más sencilla y visual de crear un issue es directamente desde la interfaz web de GitHub.

Acceder al Repositorio

Navega a github.com/usuario/repositorio

Ir a la pestaña Issues

Haz clic en "Issues" en el menú superior del repositorio

Crear Nuevo Issue

Presiona el botón verde "New issue"

Completar Formulario

Añade título descriptivo y descripción detallada

Configurar Metadatos

Asigna labels, assignees, projects y milestones

Enviar Issue

Haz clic en "Submit new issue"

GitHub CLI - Crear Issues

Comando Básico

Bash 
# Forma interactiva
gh issue create

# Con parámetros directos
gh issue create --title "Bug en login" \
  --body "Descripción del problema"

Issue Completo

Bash Avanzado 
gh issue create \
  --title "Feature: Autenticación OAuth" \
  --body "Implementar OAuth 2.0" \
  --label "enhancement" \
  --label "security" \
  --assignee "@me" \
  --milestone "v2.0"

Comandos

gh issue view 42           # Ver issue #42
gh issue close 42          # Cerrar issue
gh issue comment 42        # Comentar

Python - Issue Completo

Python Avanzado 
from github import Github
from datetime import datetime

# Configuración
token = "ghp_token"
g = Github(token)
repo = g.get_repo("usuario/proyecto")

# Obtener labels y usuarios
bug_label = repo.get_label("bug")
priority_label = repo.get_label("high-priority")
assignee = g.get_user("nombre-usuario")

# Crear issue completo
issue = repo.create_issue(
    title="⚠️ Critical: Database failures",
    body=f"""## 🐛 Bug Description
Database connection failures occurring.

## 📊 Details
- **Error:** Connection timeout
- **Frequency:** ~20/hour
- **Impact:** High
- **Timestamp:** {datetime.now().isoformat()}

## 🔍 Steps to Reproduce
1. Run concurrent queries
2. Wait 2-5 minutes
3. Observe timeout

## 💡 Proposed Solution
- Increase connection pool
- Implement retry logic
- Add circuit breaker
    """,
    labels=[bug_label, priority_label],
    assignee=assignee
)

# Añadir comentario
issue.create_comment(
    "📌 Auto-created by monitoring system"
)

print(f"✅ Issue #{issue.number} created")
print(f"🔗 {issue.html_url}")

Python con Requests (API REST)

Python + Requests 
import requests

# Configuración
TOKEN = "ghp_token"
OWNER = "usuario"
REPO = "proyecto"

headers = {
    "Authorization": f"token {TOKEN}",
    "Accept": "application/vnd.github.v3+json"
}

url = f"https://api.github.com/repos/{OWNER}/{REPO}/issues"

# Datos del issue
data = {
    "title": "✨ Feature: Dark Mode",
    "body": """## 🎨 Description
Implement dark mode for better UX.

## 📝 Requirements
- [ ] Toggle in settings
- [ ] Persist user preference
- [ ] Apply to all views
- [ ] Smooth transition
    """,
    "labels": ["enhancement", "ui/ux"],
    "assignees": ["dev1"]
}

# Crear issue
response = requests.post(url, headers=headers, json=data)

if response.status_code == 201:
    issue = response.json()
    print(f"✅ Issue #{issue['number']} created")
    print(f"🔗 {issue['html_url']}")
else:
    print(f"❌ Error: {response.status_code}")

Método 4: JavaScript con Octokit

Instalación

npm 
npm install @octokit/rest

Ejemplo Básico

JavaScript 
const { Octokit } = require("@octokit/rest");

const octokit = new Octokit({
  auth: process.env.GITHUB_TOKEN
});

async function createIssue() {
  const response = await octokit.rest.issues.create({
    owner: "usuario",
    repo: "proyecto",
    title: "🐛 Bug: Form validation error",
    body: `## Problem Description
Form doesn't validate emails properly.

## Steps to Reproduce
1. Go to /register
2. Enter invalid email
3. Click Submit
4. Form submits without validation
    `
  });

  console.log(`✅ Issue #${response.data.number}`);
  console.log(`🔗 ${response.data.html_url}`);
}

createIssue();

JavaScript - Issue Avanzado

JavaScript Avanzado 
const { Octokit } = require("@octokit/rest");

const octokit = new Octokit({
  auth: process.env.GITHUB_TOKEN
});

async function createDetailedIssue() {
  const owner = "usuario";
  const repo = "proyecto";
  
  // Crear issue
  const issue = await octokit.rest.issues.create({
    owner,
    repo,
    title: "✨ Feature: Advanced Search",
    body: `## 🎯 Objective
Add advanced search with multiple filters.

## 📋 Functional Requirements
- [ ] Full-text search
- [ ] Category filters
- [ ] Date filters
- [ ] Result sorting
- [ ] Pagination

## 💡 Technical Proposal
- Backend: Elasticsearch
- Frontend: React Query
- API: GraphQL

## ⏱️ Estimation
8-10 development days
    `,
    labels: ["enhancement", "high-priority"],
    assignees: ["dev1", "dev2"],
    milestone: 3
  });

  // Agregar comentario
  await octokit.rest.issues.createComment({
    owner,
    repo,
    issue_number: issue.data.number,
    body: "👋 @team Needs architecture review"
  });

  console.log(`✅ Issue #${issue.data.number} created`);
  console.log(`🔗 ${issue.data.html_url}`);
}

createDetailedIssue();
