Customer Journey Map

Las 5 Fases del viaje

  • Descubrimiento: El consumidor conoce el producto. No se busca vender; solo se informa que existe una solución a su necesidad.
  • Consideración: El usuario evalúa opciones. Debe conocer la marca y sus puntos fuertes. Se lanza un mensaje más directo e incentivador.
  • Compra: El usuario decide y ejecuta. Un proceso digital fluido y personal de tienda capacitado son clave.
  • Retención: Post-venta. Se busca mantener la satisfacción y propiciar compras repetidas (fidelización).
  • Recomendación: Clientes satisfechos mejoran la imagen de marca. Redes sociales, valoraciones y boca-a-boca son los motores.
Diseño de Software

¿Qué es el Diseño?

El diseño es tanto el proceso de definir la arquitectura de un sistema como el resultado de ese proceso.
Sistema

Entidad lógica con un conjunto de responsabilidades. Puede consistir de hardware, software o ambos.

Subsistema

Sistema que es parte de uno mayor. Tiene una interfaz bien definida y objetos altamente acoplados internamente.

Componente

Pieza de software con un rol claro. Puede ser aislada y reemplazada. Muchos están diseñados para ser reutilizables.

Módulo

Componente definido a nivel de lenguaje de programación. Equivale a un Package o Namespace.

Diseño de Software

Proceso de Diseño

Diseño arquitectónico

Se define la arquitectura global del sistema. Se elige un patrón: Capas MVC Microservicios SOA

Especificación abstracta

Se especifican los subsistemas. Cada subsistema realiza un servicio importante, es relativamente independiente y contiene objetos altamente acoplados.

Diseño de la interfaz

Se describen las interfaces de los subsistemas. Permite usarlos como caja negra desde el exterior.

Diseño de componentes

Cada subsistema se descompone en componentes y se diseñan sus interfaces internas.

Diseño de estructura de datos y algoritmos

Especificación detallada de las estructuras de datos y algoritmos que implementan cada componente.

Diseño de Software

Principios del Diseño

  • Dividir y Conquistar: Partir un problema grande en partes más pequeñas y manejables reduce la complejidad general.
  • Incrementar la Cohesión: Un módulo cohesivo agrupa cosas relacionadas y excluye las que no lo son.
  • Reducir el Acoplamiento: Eliminar o reducir la interdependencia innecesaria entre módulos.
  • Nivel de Abstracción Alto: Ocultar detalles de implementación para reducir la complejidad visible.
  • Incrementar Reusabilidad: Diseñar componentes para que puedan usarse en distintos contextos.
  • Flexibilidad y Anticipación: Prever cambios futuros en tecnología o requisitos. Por ej., pantallas responsive.
Principios del Diseño

Cohesión

Un módulo o subsistema tiene alta cohesión si mantiene juntas las cosas relacionadas y deja fuera las que no lo son.

Baja Cohesión

Elementos mezclados sin relación clara entre sí.

🔷🔷
🔵🔵🔵
Alta Cohesión

Cada módulo agrupa solo elementos del mismo tipo.

Objetivo

Diseñar servicios robustos cuyos elementos estén fuerte y genuinamente relacionados entre sí. Alta cohesión favorece la comprensión y facilita los cambios. El objetivo es maximizar la cohesión.

Principios del Diseño

Acoplamiento

El acoplamiento mide la fortaleza de la asociación entre módulos. Un bajo acoplamiento indica un sistema bien dividido, donde cada componente es tan independiente como sea posible.
🟥↔🔺
↕   ↕
🔵↔🟣
Alto Acoplamiento

Módulos interconectados en todas direcciones. Cambiar uno afecta a todos.

🟥—🔺
     
🔵—🟣
Bajo Acoplamiento

Relaciones mínimas y bien definidas. Módulos independientes.

Fuertemente Acoplados

Usan variables compartidas o intercambian información de control. Dificulta el mantenimiento.

Débilmente Acoplados

Se comunican solo por parámetros bien definidos. Evitan variables globales compartidas.

Diseño de Software

Co-nascencia — Connascence

Dos partes son co-nascentes si un cambio en una de ellas requiere modificar la otra para mantener la corrección general del sistema.
Connascence Estática
  • Nombres de variables y clases
  • Tipos de datos
  • Significados o convenciones
  • Posición de parámetros
  • Algoritmos compartidos
Connascence Dinámica
  • Orden de ejecución
  • Tiempo de respuesta
  • Valores en tiempo de ejecución
  • Identidad de objetos
La connascence refina los conceptos de acoplamiento eferente (lo que usa un módulo) y aferente (quien usa un módulo).
Modelado con UML

¿Qué es UML?

Definición

El Lenguaje Unificado de Modelado es una familia de notaciones gráficas respaldadas por un único metamodelo que ayuda a describir y diseñar sistemas de software, especialmente los construidos con el paradigma orientado a objetos (OO).

  • Apareció en 1997. Es un estándar abierto controlado por el Object Management Group (OMG).
  • Unificó muchos lenguajes gráficos preexistentes y se convirtió en la herramienta estándar para los desarrolladores de software.
  • Los diagramas se dividen en dos grandes familias: Estructurales (qué es el sistema) y de Comportamiento (cómo actúa el sistema).
UML

Diagramas Estructurales

Muestran la estructura estática del sistema y sus partes en diferentes niveles de abstracción.

📐
Clases
Tipos de objetos, atributos, operaciones y relaciones estáticas.
🧩
Componentes
Relación estructural de componentes que se comunican por interfaces.
📦
Paquetes
Sistema dividido en agrupaciones lógicas y sus dependencias.
🖥️
Despliegue
Hardware, software y su configuración física de despliegue.
🔷
Objetos
Relación entre objetos en un momento dado del sistema.
🏗️
Estructura Compuesta
Estructura interna de una clase compleja.
UML

Diagramas de Comportamiento

Muestran el comportamiento dinámico de los objetos en el sistema.

👤
Casos de Uso
Actores, funciones del sistema y sus interacciones. Representa requisitos funcionales.
▶️
Actividad
Flujo de trabajo desde un punto inicial a uno final. Documenta requisitos de negocio.
💬
Secuencia
Intercambio de mensajes entre instancias en orden temporal.
🔄
Comunicación
Como secuencia, pero con foco en los mensajes pasados entre objetos.
🔀
Máquina de Estado
Comportamiento de objetos según el estado en que se encuentran.
⏱️
Tiempo
Comportamiento de los objetos en un marco de tiempo dado.
UML — Diagramas Clave

Diagramas más utilizados

Casos de Uso

Narrativa de cómo los actores (usuarios y sistemas externos) usan el sistema. Los actores se entienden como "perfiles".

Diagrama de Clase

Describe tipos de objetos, sus propiedades, operaciones y relaciones. Para sistemas grandes, dividirlos en diagramas más pequeños vinculados.

Diagrama de Secuencia

Representa el intercambio de mensajes entre instancias para cumplir una funcionalidad. Define el comportamiento dinámico.

Despliegue + Componentes

Usados juntos: los componentes muestran qué existe y cómo se relacionan; el despliegue muestra en qué nodos físicos residen.

Resumen

Lo que vimos en UT3

Customer Journey Map

Herramienta para mapear emociones del usuario en 5 fases: Awareness, Consideration, Purchase, Retention, Advocacy.

Proceso de Diseño

Arquitectónico → Abstracto → Interfaz → Componentes → Algoritmos. Cada nivel más detallado que el anterior.

Cohesión

Maximizar la cohesión: cada módulo hace una sola cosa bien. Favorece comprensión y mantenimiento.

Acoplamiento

Minimizar el acoplamiento: módulos independientes, interfaz por parámetros, sin variables globales compartidas.

UML

Estándar OMG desde 1997. Diagramas estructurales (clases, componentes, paquetes) y de comportamiento (casos de uso, secuencia, actividad).

Connascence

Refinamiento del acoplamiento. Estática (nombres, tipos) vs Dinámica (orden, tiempo, identidad).
