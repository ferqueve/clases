Conceptos base

¿Qué es un Diagrama de Despliegue?

Definición

Es un diagrama UML estructural que modela la arquitectura física de un sistema: muestra cómo el software se distribuye sobre el hardware, qué nodos existen, qué artefactos corren en cada uno y cómo se comunican.

¿Para qué sirve?

Permite visualizar la infraestructura de despliegue, planificar la distribución de componentes, identificar puntos únicos de fallo y documentar sistemas distribuidos, microservicios o aplicaciones en la nube.

¿Cuándo se usa?

En la fase de diseño arquitectónico: para comunicar la infraestructura al equipo de operaciones, documentar sistemas existentes o planificar migraciones entre entornos.

Elementos del diagrama

Componentes UML

«node» / «device»
Nodo

Recurso computacional físico o virtual donde se ejecutan artefactos: servidor, PC, dispositivo, VM o contenedor.

«artifact»
Artefacto

Elemento de software desplegado en un nodo: .jar, .war, .exe, base de datos, archivo de configuración.

«communication path»
Ruta de Comunicación

Línea entre nodos que indica la conexión de red: HTTP, TCP, REST, JDBC, MongoDB Wire, Kafka Protocol…

«executionEnvironment»
Entorno de Ejecución

Contenedor de ejecución software dentro de un nodo: JVM, servidor web, Docker, Node.js runtime.

Notación Visual

Los nodos se dibujan como cajas 3D (rectángulo con aristas visibles en la esquina superior derecha). Los artefactos aparecen como rectángulos dentro del nodo con el ícono de documento y el stereotype «artifact».

Ejercicio 1 · E-Commerce

Sistema de Comercio Electrónico

1
Interfaz de Usuario

App React servida a través de un balanceador de carga NGINX que distribuye solicitudes a tres servidores web Linux.

2
Backend de Lógica

Construido con Java Spring. Se comunica con los servidores web, con PostgreSQL (datos de usuarios) y MongoDB (datos de productos).

3
Cola de Mensajes

Apache Kafka maneja comunicaciones asíncronas: actualizaciones de inventario y notificaciones de usuarios en tiempo real.

4
Servidor de Archivos Compartido

Todos los servidores tienen acceso a un servidor de archivos independiente con archivos de configuración y datos compartidos.

Ejercicio 2 · Multiplataforma + DW

App Multiplataforma y DataWarehouse

1
Apps Clientes (Android, iOS, Desktop)

Android (Google Play), iOS (App Store) y escritorio (Windows/macOS/Linux desde el sitio web). Todas se comunican con el backend vía API RESTful.

2
Backend + Base de Datos Replicada

Java Spring con esquema maestro-esclavo. El nodo maestro (PostgreSQL) almacena todos los datos; las esclavas replican para redundancia y balanceo de carga de lectura.

Pentaho extrae, transforma y carga datos en el DataWarehouse. Tableau consume el DW para generar análisis e informes de negocio.

Conclusiones

Lo aprendido

Los diagramas de despliegue modelan la infraestructura física, identificando nodos, artefactos y rutas de comunicación entre ellos.

Cuándo usarlos

En arquitecturas distribuidas, microservicios, sistemas cloud, o siempre que necesitemos comunicar dónde vive cada componente y cómo se conecta.

Diferencia clave

El diagrama de componentes muestra qué hace el software; el de despliegue muestra dónde vive, en qué hardware y cómo se conecta.

Buenas prácticas

Indicar siempre el protocolo en cada ruta, usar correctamente los stereotypes («node», «artifact», «device») y agrupar artefactos dentro de su nodo contenedor.
