Experimento realizado con 3 datasets de distintas configuraciones, incluyendo el efecto borde. Se presentan los datos obtenidos, las regresiones lineales y las conclusiones de diseño.

Marco teórico

La fórmula que guía el experimento

MT  =  a  +  b · log₂( 2A / W )  =  a + b · ID

Tiempo (ms)

Índice dificultad (bits)
¿Qué predice?

El tiempo para alcanzar un objetivo aumenta linealmente con el ID. Si graficamos MT vs ID, debemos obtener una línea recta.

Efecto borde

Cuando el objetivo está en el borde, el cursor se detiene solo: W efectivo → ∞, ID → 0. El MT disminuye drásticamente.

Throughput

TP = ID / MT en bits/s. Mide la eficiencia del sistema humano‑dispositivo. Mayor TP = más eficiente.

Diseño del experimento

Conclusión 1

C1: La ley de Fitts predice bien el movimiento humano

Hallazgo

En los tres datasets se obtuvo R² > 0.98, lo que confirma que la relación entre el Índice de Dificultad (ID) y el tiempo de movimiento (MT) es efectivamente lineal, tal como predice el modelo de Fitts.

  • ✓
    ID más alto → siempre implica MT mayor. La relación es monotónica y lineal.
  • ✓
    Los outliers humanos (reacción lenta, distracción) se alejan de la recta pero no la destruyen.
Implicación para diseño: dado que el modelo es predecible, se puede estimar el tiempo de interacción con un diseño antes de construirlo, simplemente calculando el ID de cada target.
Conclusión 2

C2: El efecto borde reduce el MT hasta un 42%

Hallazgo

Con borde activado, el MT promedio cayó un 38% y la pendiente b de la regresión bajó de 147 a 85 ms/bit (–42%). El throughput casi se duplicó: de 4.2 a 7.8 bits/s. El borde convierte al cursor en un aliado automático.

¿Por qué ocurre esto?
  • 1
    El borde físico actúa como tope automático: no hay que frenar con precisión.
  • 2
    El W efectivo del objetivo se vuelve prácticamente infinito → ID ≈ 0.
  • 3
    La energía cognitiva y motriz se dirige solo al movimiento rápido, no a la parada precisa.
Implicación: macOS coloca la barra de menú en el borde superior de toda la pantalla. Windows la puso dentro de cada ventana → más lenta de alcanzar.
Conclusión 3

C3: Mismo ID → mismo MT, sin importar A y W

Hallazgo

En DS3, los tres pares del grupo A (ID ≈ 2.0 bits) registraron un MT de 382–405 ms. Los tres pares del grupo B (ID ≈ 4.1 bits) registraron 695–718 ms. La dispersión dentro de cada grupo fue de solo ~23 ms, muy inferior a la diferencia entre grupos (~300 ms).

Implicaciones de diseño
  • →
    Un botón pequeño y cercano puede ser tan fácil como uno grande y lejano si tienen igual ID.
  • →
    Para reducir el tiempo de uso no alcanza con agrandar: también hay que acercar el target.
  • →
    El ID es la métrica unificada para comparar la usabilidad de cualquier elemento de UI.
Diseño UI

De los datos a las decisiones de diseño

Los tres hallazgos experimentales se traducen en guías concretas para el diseño de interfaces.

Prácticas recomendadas
  • ↑W
    Botones grandes para acciones frecuentes o críticas (guardar, confirmar).
  • ↓A
    Elementos cercanos al área de trabajo habitual del usuario: menús contextuales, popups próximos al cursor.
  • ∞W
    Aprovechar los bordes para acciones globales: dock, taskbar, menú global (macOS).
  • ⚡
    Esquinas para acciones de alta prioridad: el cursor queda atrapado, W infinito en 2D.
  • 📱
    En móviles: mínimo 44×44 pt (HIG) – 48×48 dp (Material). El dedo tiene mayor W efectivo que el mouse.
Errores que aumentan el ID
  • ✗
    Targets pequeños para acciones destructivas (eliminar, cerrar sin confirmación).
  • ✗
    Menús en barras de herramientas flotantes lejos del área de trabajo.
  • ✗
    Botones "OK" y "Cancelar" con el mismo tamaño y cerca entre sí: alta tasa de clic erróneo.
  • ✗
    Listas desplegables largas donde los ítems frecuentes están al final.
Cada vez que un usuario se equivoca de botón, el culpable puede ser un ID mal calculado.
