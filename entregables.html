Entregables del Proyecto

Objetivo

Durante el desarrollo del proyecto, se deben generar 5 documentos principales que documentan todas las fases del ciclo de vida del software, desde el relevamiento inicial hasta el manual técnico final.

Importancia

  • Documentación profesional
  • Trazabilidad del proyecto
  • Comunicación con el cliente
  • Base para el desarrollo

Cronograma

  • Semana 1: Relevamiento
  • Semana 2: Diseño
  • Semana 3: Implementación
  • Validaciones con cliente

Documento de Relevamiento de Requerimientos

Semana 1

Contenido Principal

BEs

Business Events

Eventos del negocio que desencadenan procesos en el sistema.

Ejemplo: "Cliente solicita presupuesto"

BUCs

Business Use Cases

Casos de uso del negocio que describen procesos completos.

Ejemplo: "Gestión de ventas"

PUCs

Process Use Cases

Casos de uso de proceso que detallan actividades específicas.

Ejemplo: "Registrar pago"
Importante: Este documento surge de las actividades de relevamiento y entrevistas realizadas durante la Semana 1.

Requerimientos Funcionales y No Funcionales

Validación: Lunes 15

Plantilla Volere

Requerimientos Funcionales (RF)

  • Qué debe hacer el sistema
  • Funcionalidades específicas
  • Comportamientos esperados
  • Casos de uso detallados
Ejemplo:
"El sistema debe permitir registrar nuevos clientes con sus datos de contacto"

Requerimientos No Funcionales (RNF)

  • Restricciones del sistema
  • Calidad y rendimiento
  • Seguridad y usabilidad
  • Tecnologías requeridas
Ejemplo:
"El sistema debe responder en menos de 2 segundos para el 95% de las operaciones"

Diagramas Requeridos

  • Diagramas de Casos de Uso: Actores e interacciones
  • Identificar actores principales
  • Diagramas de Actividades: Flujos de trabajo
  • Procesos paso a paso

Documento de Diseño del Sistema

Semana 2

Diseño Técnico Completo

Nota Importante: Todo se entrega consolidado en un único documento de diseño, no separado en múltiples PDFs.

Diagramas UML

  • Diagramas de Clases: Estructura del sistema
  • Diagramas de Paquetes: Organización lógica
  • Diagramas de Secuencia: Interacciones temporales
  • Diagramas de Componentes: Arquitectura modular
  • Diagramas de Despliegue: Infraestructura física

Diseño de Base de Datos

  • MER: Modelo Entidad-Relación
  • MDR: Modelo de Datos Relacional
  • Diccionario de Clases: Atributos y métodos
  • Diseño de BD: Tablas, campos, tipos de datos
Consejo de Organización: Utiliza herramientas como Visual Paradigm, Draw.io o Lucidchart para mantener consistencia en todos los diagramas.

Prototipo de Interfaces de Usuario

Diseño Visual en Figma

Características del Prototipo

  • Diseño visual de todas las pantallas
  • Navegación interactiva entre vistas
  • Componentes reutilizables
  • Guía de estilos (colores, tipografías)
  • Responsive design (móvil y desktop)
  • Flujos de usuario completos
  • Estados de la interfaz (hover, active)
  • Iconografía y recursos visuales
Importante: Este NO es solo un entregable visual, es un entregable formal que debe ser presentado y validado con el cliente.

Qué Incluir

  • Pantallas de inicio y login
  • Dashboard principal
  • Formularios de captura de datos
  • Listados y tablas
  • Mensajes de error y confirmación
  • Menús de navegación

Herramientas Recomendadas

  • Figma: Recomendado (gratuito)
  • Adobe XD: Alternativa profesional
  • Sketch: Para Mac users
  • Balsamiq: Wireframes rápidos

Organización con Trello y Kanban

¿Por qué usar Trello?

  • Herramienta gratuita y fácil de usar
  • Colaboración en tiempo real
  • Visualización clara del progreso
  • Acceso desde cualquier dispositivo
  • Asignación de responsables
  • Fechas límite y recordatorios
  • Adjuntar archivos y documentos
  • Historial de cambios

Metodología Kanban

Kanban es un método visual para gestionar el trabajo. Se basa en tarjetas que se mueven a través de columnas que representan diferentes estados del proceso.

Visual

Ver todo el trabajo de un vistazo

Límites WIP

Controlar el trabajo en progreso

Flujo Continuo

Mejora continua del proceso

Consejo: Puedes agregar columnas adicionales según las necesidades del equipo, como "En Revisión" o "Testing", pero mantén la estructura simple y clara.
Límite WIP (Work In Progress): No sobrecargues la columna "En Progreso". Limita la cantidad de tareas simultáneas (recomendado: 2-3 tareas por persona).

Recomendaciones de Uso

Gestión de Tarjetas

  • Títulos claros: "Crear diagrama de clases" mejor que "Diagrama"
  • Descripciones completas: Especifica qué se debe hacer
  • Checklists: Divide tareas grandes en subtareas
  • Etiquetas de color: Categoriza (Documentación, Diseño, etc.)
  • Fechas límite: Asigna deadlines realistas

Trabajo en Equipo

  • Asigna responsables: Cada tarjeta debe tener un owner
  • Comentarios: Comunica avances y bloqueos
  • Adjunta archivos: Sube documentos relevantes
  • Daily stand-up: Revisa el tablero diariamente
  • Actualiza el estado: Mueve tarjetas al cambiar de fase

Ejemplo de Organización por Entregables

Etiqueta: Relevamiento
  • ✓ Entrevistar cliente
  • ✓ Identificar BEs
  • ✓ Documentar BUCs y PUCs
Etiqueta: Diseño
  • ✓ Crear diagrama de clases
  • ✓ Diseñar MER
  • ✓ Prototipo en Figma
Mejora Continua: Realiza retrospectivas semanales para identificar qué está funcionando bien y qué se puede mejorar en el proceso.
